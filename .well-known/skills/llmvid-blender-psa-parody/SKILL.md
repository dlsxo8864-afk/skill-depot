# 블렌더 공익 안내 패러디 쇼츠 (llmvid-blender-psa-parody)

검증된 예제와 절차를 묶은 팩이다. 버튼 하나로 끝나는 자동 도구가 아니다.
`example/`의 스크립트로 공통 예제 대본 「점심 메뉴 정하는 법」(15초, 360프레임)을 실제로 만들었다. 같은 묶음의 다른 팩도 모두 이 대본을 쓰고, 팩마다 화풍과 연출만 다르다. 새 대본은 **타임라인 JSON 한 파일**(샷·인물·동작·소품·안내 틀·자막)을 새로 써서 만든다. 세트 2종, 동작 9종, 소품 3종 안에서는 파이썬을 고치지 않고 장면 수·장소·카메라·동작을 바꿀 수 있다.

형식은 인스타그램의 생활 안전 수칙 패러디 연작을 보고 정했다. 화면 틀(왼쪽 위 수칙 번호 배지와 제목, 아래 진녹색 상자 자막, 고정된 끝맺음 문구)과 대본 공식(일상 습관 → 과장된 인과 → 엉뚱한 제도나 장치로 마무리)만 따왔다. 그 계정의 캐릭터·제목·대본은 쓰지 않았고 예제 대본은 새로 썼다. 참고한 연작은 게임 엔진풍 사실 화풍에 AI 합성 표시가 붙어 있어 실제 3D인지 AI 영상인지 화면만으로 단정할 수 없었다. 이 팩은 같은 형식을 관절 인형풍 인물로 코드만으로 재현한다.

세트·인물·소품은 전부 코드로 만든 도형이다. 외부 3D 모델·텍스처·HDRI·이미지가 필요 없고, 영상·이미지 생성 AI 없이 블렌더와 ffmpeg만으로 끝까지 만든다.

```
llmvid-blender-psa-parody/
  SKILL.md
  LICENSES.md
  example/
    create_psa.py           타임라인을 읽어 세트·인물·소품·카메라·동작을 만들고 .blend 로 저장한다(시작점)
    timeline.example.json   [대본] 예제 타임라인. 샷 5개, 인물 3명(나·민수·팀장), 팻말 10개, 안내 틀, 자막 5줄
    preview_checks.py       저장한 .blend 에서 샷마다 스틸을 1장 또는 3장 뽑는다
    render_final.py         전체 프레임을 PNG 로 뽑는다(끊겨도 다시 실행하면 이어서)
    finish.py               프레임 + 음성 + 안내 틀(배지·제목·자막·끝맺음)을 MP4 로 합친다
    fontfind.py             한글 글꼴을 찾는다(자막과 팻말 글자에 쓴다)
    sheet.py                그림 여러 장을 한 장 시트로 붙인다(검수용)
```

## 1. 이 스킬이 만드는 것

- 관절 인형풍 인물(키 약 1.75 m): 둥근 몸통, 원기둥 팔다리, 머리 캡, 검은 눈. 의상 4종(knit, uniform(모자·벨트·견장), coat(무릎까지), hoodie(후드)).
- 세트 2종: 방(room: 책상·모니터·휴대폰·콘센트에 꽂힌 충전기와 녹색 불·케이블·의자·침대·선반·스탠드·문·창·천장), 밤거리 교차로(street_night: 차도·보도·횡단보도·차선·창에 불 켜진 빌딩·빨간 신호등 4개·정차한 차·교차로 위 조명. 가로등은 일부러 없다).
- 소품 3종: 팻말(sign, 한글 글자, 튀어나오며 등장), 상자(box), 고깔(cone).
- 동작 9종: idle, walk, reach, bow, nod, point, shrug, sit, glow(몸이 빛나 주변을 밝힌다).
- 화면 틀: 왼쪽 위 녹색 배지(수칙 번호) + 흰 제목, 아래 진녹색 상자 자막, 끝맺음 문구(바탕 없는 흰 글자).
- 결과: 1080×1920 세로, 24fps MP4. 예제는 15초(360프레임).

가장 중요한 한계
- **표정과 입 연기가 없다.** 눈만 있다(`eyes: false`면 눈도 없다).
- **물건을 잡지 못한다.** reach는 팔을 뻗는 자세일 뿐 물건이 따라오지 않는다.
- **동작 9종, 세트 2종, 소품 3종 밖은 코드를 짜야 한다.** `ACTIONS`, `SETS`, `PROPS`에 함수를 더한다.
- **사실적인 사람이 아니다.** 원본 연작 같은 사실 화풍 인물이 필요하면 사람 모델 애드온(예: MPFB2)을 붙여야 하는데, 설치와 내려받기가 필요해 이 팩에는 넣지 않았다.

잘 맞는 대본
- "~하면 ~됩니다" 식 생활 수칙 패러디. 사소한 습관 → 과장된 결과 → 엉뚱한 제도로 마무리.
- 방과 거리를 오가며, 결과를 '빛나는 사람', '팻말', '부감 전경' 같은 한 장면 개그로 보여 주는 이야기.
- 10~40초, 컷 3초 안팎, 차분한 안내 방송 말투의 내레이션.

안 맞는 대본
- **대화 연기나 표정 반응이 웃음의 핵심인 이야기.**
- 차 추격처럼 많은 것이 동시에 움직이는 장면(인물과 소품을 하나씩 적어야 한다).
- **실제 정부·지자체·공공기관 이름이나 로고를 쓰는 패러디.** 진짜 공익광고로 오인될 수 있으니 배지·제목에는 가상의 이름만 쓴다. 예제의 '생활 안내 제12호'는 가상의 이름이다.

## 2. 입력

| 입력 | 필수 | 설명 |
|---|---|---|
| 대본 | 필수 | 내레이션 문장과 장면 나눔. 마지막 끝맺음 문구 한 줄 |
| 타임라인 파일 | 필수 | 샷·인물·동작·소품·안내 틀·자막 JSON(`example/timeline.example.json` 본뜸, 형식은 5절) |
| 음성 파일 | 선택 | wav/mp3. 없으면 소리 없는 영상(조용한 오디오 트랙)이 된다 |
| 배경음 파일 | 선택 | wav/mp3. 음량 0.3으로 섞인다 |
| 저장 폴더 | 필수 | 작업 폴더. 예제 360프레임 PNG가 약 627MB다 |

## 3. 먼저 확인할 환경

```bash
blender --version      # Blender 5.2.3 LTS 에서 전 과정을 확인했다. 4.5 LTS 는 확인하지 못했다(코드에는 4.x 경로도 넣어 두었다). PATH 에 없으면 실행 파일 위치를 사용자에게 묻는다
ffmpeg -version        # libx264, libass(자막 필터)가 든 빌드
python --version       # 3.10 이상
python -c "import PIL; print(PIL.__version__)"   # Pillow (sheet.py 검수 시트에만 쓴다)
```

- 없는 도구가 있으면 사용자에게 알리고 설치 여부를 묻는다. 프로그램 설치나 내려받기는 사용자 허가를 받은 뒤에만 한다.
- 한글 글꼴: `python scripts/fontfind.py`로 확인한다. Noto Sans KR → 맑은 고딕 순으로 찾는다. 자막(`finish.py`)과 팻말 글자(`create_psa.py`)가 이 글꼴을 쓴다. 팻말 글꼴을 못 찾으면 `FONT_WARNING`이 찍히고 블렌더 기본 글꼴로 넘어가 한글이 깨진다. 이때는 사용자에게 글꼴 파일을 받는다.
- EEVEE는 그래픽 카드를 쓴다. 시험 환경은 Windows 10 + RTX 3070 Ti 8GB다. 그래픽 카드가 없는 PC는 확인하지 못했다.
- 외부 3D 모델·텍스처·HDRI를 쓰지 않으므로 에셋 내려받기는 필요 없다.

## 4. 절차

작업 폴더를 따로 만들고 그 안에서 명령을 돌린다. 팩의 `example/`은 원본으로 두고 작업 폴더의 `scripts/`로 복사해 쓴다. 새 대본의 타임라인은 작업 폴더에 `timeline.json`으로 새로 쓴다.

```
작업 폴더/
  scripts/                 example 사본
  timeline.json            새 대본의 타임라인(scripts/timeline.example.json 을 본떠 쓴다)
  scene.blend              1단계 결과
  previews/                2단계 결과 proof_<순번>_<샷 id>_<프레임>.png
  proofs.png               3단계 검수 시트
  frames/                  4단계 결과 frame_0001.png ~ , _signature.txt
  render-manifest.json     4단계 결과(.blend 옆에 생긴다)
  subs.ass, fonts/         5단계 finish.py 가 만든다
  out.mp4                  최종 영상
```

경로 규칙. 셋이 서로 달라서 헷갈린다.
- `create_psa.py`에 넘기는 상대 경로는 **지금 있는 폴더 기준**이다. 그래도 타임라인과 .blend는 **절대 경로**로 넘기는 습관을 들인다(복셀 팩은 스크립트 폴더 기준이라 두 팩을 오가면 틀리기 쉽다).
- `preview_checks.py`, `render_final.py`의 출력 폴더 상대 경로는 **열린 .blend가 있는 폴더 기준**이다.
- `finish.py`는 **지금 있는 폴더**에 `subs.ass`와 `fonts/`를 만든다. 작업 폴더에서 실행한다.

### 0단계. 대본을 샷 표로 나눈다

예제의 샷 5개는 다음과 같다.

| 순번 | 샷 id | 시작(초) | 끝(초) | 세트 | 장면 | 자막 |
|---|---|---|---|---|---|---|
| 1 | hook | 0.0 | 3.0 | room(낮) | 내가 책상 앞에서 손을 뻗고(reach), 2.25초에 "오늘 뭐 먹죠?" 팻말이 솟는다 | 점심 메뉴, / 오늘도 못 정했죠? |
| 2 | ask | 3.0 | 6.0 | hook 세트 재사용 | 민수와 팀장이 차례로 으쓱하고(shrug) "아무거나" 팻말이 하나씩 솟는다 | 물어보면 다들 / "아무거나요." |
| 3 | wait | 6.0 | 9.0 | hook 세트 재사용(저녁, 조명 0.6) | 내가 앉아 고개를 떨군다. "11:50" 팻말 옆에 "12:20 배고픔 100%" 팻말이 솟는다 | 시계는 가고, / 배는 고파 오고. |
| 4 | decide | 9.0 | 12.0 | street_night(밤) | 빛나는 팀장이 걸어와 가리키고 "그럼 김치찌개" 팻말이 솟는다 | 결국 팀장님이 / 정합니다. |
| 5 | punch | 12.0 | 15.0 | decide 세트 재사용 | 둘이 인사하고(bow) "김치찌개" 팻말이 늘어난다. 13.4초에 빨간 "결정" 팻말 | 오늘도 / 김치찌개입니다. (13.9초부터 끝맺음) |

- 대본 공식: 1컷 습관 제시 → 2컷 엉뚱한 원인 → 3컷 더 엉뚱한 제도 → 4컷 전경 + 끝맺음.
- 한 샷은 2~4초가 알맞다. 같은 장소를 다른 각도·시간대로 다시 보여 줄 때는 `reuse_set`을 쓴다.
- 샷은 빈틈없이 이어 쓴다(앞 샷 end = 다음 샷 start). 마지막 샷의 end가 영상 길이다.
- 블렌더 프레임은 1부터 센다. 샷의 첫 프레임은 `round(start × 24) + 1`, 끝 프레임은 `round(end × 24)`다.

### 1단계. 장면 만들기

```bash
blender --background --python-exit-code 1 --python scripts/create_psa.py -- "<작업 폴더 절대 경로>/timeline.json" "<작업 폴더 절대 경로>/scene.blend"
```

- 끝에 `SCENE_OK frames=<프레임 수> shots=<샷 수>`가 찍히고 .blend가 저장된다. 예제는 `SCENE_OK frames=360 shots=5`.
- 인자를 빼면 스크립트 옆 `timeline.example.json`을 읽어 스크립트 옆 `scene.blend`로 저장한다.
- 모르는 세트·시간대·동작·소품·의상 이름이나 cast에 없는 인물을 쓰면 `ValueError`로 멈추고 .blend를 저장하지 않는다(종료 코드 1).
- `GLOW_LINK_SKIPPED`가 찍히면 그 블렌더에 라이트 링킹이 없다는 뜻이다. 동작은 같고 빛나는 인물의 팔이 조금 더 밝게 보인다.

### 2단계. 샷마다 스틸 뽑기

```bash
blender --background scene.blend --python-exit-code 1 --python scripts/preview_checks.py -- previews --each 3
```

- `--each 3`이면 샷마다 앞(첫 프레임+2)·가운데·끝(끝 프레임−2) 세 장, `--each 1`이면 가운데 한 장이다. 기본 크기 50%, 16샘플(`--percent`, `--samples`로 바꾼다).
- 결과는 `previews/proof_<순번>_<샷 id>_<프레임>.png`이고 끝에 `PREVIEW_OK stills=<장수> dir=<폴더>`가 찍힌다.
- 화면 틀(배지·자막)은 아직 없다. 5단계에서 얹힌다.

### 3단계. 검수 시트 만들기

```bash
python scripts/sheet.py proofs.png previews/proof_*.png --cols 3 --width 360
```

- 셸에서 `*`가 풀리지 않으면(일부 파워셸) 파일 이름을 나열한다.
- `proofs.png`를 직접 열어 6절 기준으로 본다.

### 4단계. 전체 프레임 렌더

검수가 끝나면 원본 크기(1080×1920), 32샘플로 전체를 뽑는다. 예제 15초에 몇 분 걸리므로 백그라운드로 돌린다.

```bash
blender --background scene.blend --python-exit-code 1 --python scripts/render_final.py -- frames --samples 32
```

- `frames/frame_0001.png`부터 저장한다. 24프레임마다 `FRAME_PROGRESS`, 끝나면 `RENDER_COMPLETE {...}` 한 줄과 .blend 옆 `render-manifest.json`이 생긴다.
- 끊겨도 같은 .blend로 다시 실행하면 온전한 프레임은 건너뛴다. .blend가 바뀌면 서명(`frames/_signature.txt`)이 달라져 같은 폴더에 처음부터 다시 뽑는다.

### 5단계. 합성 (영상 + 음성 + 안내 틀)

```bash
python scripts/finish.py frames out.mp4 --timeline timeline.json --audio narration.wav
```

- **`--timeline`을 꼭 넘긴다.** 빼면 스크립트 옆 예제 타임라인의 배지·제목·자막(「점심 메뉴 정하는 법」)이 들어간다.
- 화면 틀(세로 1920 기준, 다른 크기는 비율로 맞춘다)
  - 배지 `notice.badge`: 왼쪽 위, 녹색(#1f6b3a) 상자 안 흰 글자 40px.
  - 제목 `notice.title`: 배지 바로 아래, 흰 굵은 글자 78px + 어두운 외곽선.
  - 자막 `captions`: 아래 가운데, 진녹색(#124a2e) 상자 안 흰 글자 58px. 화면 아래에서 400px 위(릴스 조작부를 피한 자리). 두 줄이면 줄마다 상자가 붙어 계단 모양이 된다.
  - 끝맺음 `notice.closing`: `closing_start`부터 끝까지, 바탕 없는 흰 글자 74px + 두꺼운 흐린 외곽선, 0.2초 페이드 인. 이때 배지·제목은 사라지고 자막은 `closing_start`에서 잘린다.
- 음성이 없으면 `--audio`를 뺀다(조용한 트랙이 들어간다). 선택: `--music 배경음`(음량 0.3), `--font 글꼴`, `--crf 20`.
- 작업 폴더에 `subs.ass`와 `fonts/`가 생긴다.

### 6단계. 최종 확인

9절 기준으로 `ffprobe`와 자막 스틸을 확인한다.

## 5. 타임라인 형식 — 대본에 맞춰 쓸 곳

새 대본에서는 이 파일만 새로 쓴다. 좌표는 세트 안 미터 단위 `[x, y, z]`이고 z가 위다. 블렌더 안에서는 세트마다 X로 400 m씩 떨어져 지어지지만, 타임라인에는 세트 안 좌표만 쓴다.

방향(`heading`, 도): 0이면 인물(과 팻말 글자 면)이 -Y를 본다(보통 카메라 쪽), 90이면 +X, 180이면 +Y, 270이면 -X. walk 중에는 걷는 방향으로 돈다.

맨 위

| 키 | 내용 | 예제 |
|---|---|---|
| `fps`, `width`, `height` | 프레임 속도, 크기 | 24, 1080, 1920 |
| `notice` | `{badge, title, closing, closing_start}` 안내 틀 | "생활 안내 제12호", "점심 메뉴 정하는 법", "오늘도 든든한\\N점심 되시기 바랍니다.", 13.9 |
| `cast` | 인물 id → 외형 | me, minsu, lead |
| `shots` | 샷 목록(시간 순) | 4개 |
| `captions` | `[{start, end, text}]` 자막 | 3줄 |

- 자막·끝맺음 줄바꿈은 JSON 안에서 `\\N`으로 쓴다(ASS 줄바꿈). 팻말 글자 줄바꿈은 `\n`이다.
- `closing`이 없으면 배지·제목·자막이 끝까지 나온다.

cast (인물 외형)

| 키 | 값 | 기본값 |
|---|---|---|
| `skin`, `hair`, `top`, `bottom`, `shoes` | `"#RRGGBB"` | `#e8bf9a`, `#1c1a19`, `#1f1f22`, `#3a3f4a`, `#e9e9e9` |
| `outfit` | `knit`, `uniform`, `coat`, `hoodie` | `knit` |
| `eyes` | `true`, `false` | `true` |

샷

| 키 | 내용 | 기본값 |
|---|---|---|
| `id` | 샷 이름. 마커·스틸 파일 이름에 쓰인다. 겹치면 안 된다 | 필수 |
| `start`, `end` | 초 | 필수 |
| `set` | `room`, `street_night` — 새 세트를 짓는다 | `set`과 `reuse_set` 중 하나 |
| `reuse_set` | 앞 샷 id. 그 샷의 세트를 그대로 쓴다 | |
| `set_options` | 세트별 옵션(아래 표) | `{}` |
| `time` | `day`, `evening`, `night` | `day` |
| `lamps` | 세트 조명 세기 배율(예제 wait 샷은 0.6으로 낮춰 저녁 느낌을 냈다) | 1.0 |
| `camera` | `from`, `to`, `look_from`, `look_to`, `lens` | from `[0,-5,2]`, to = from, look_from `[0,0,1]`, look_to = look_from, lens 35 |
| `actors` | `[{who, at, heading, actions}]` | `[]` |
| `props` | `[{kind, at, heading, ...}]` 이 샷에서만 보이는 소품 | `[]` |

- 카메라는 샷 안에서 `from`→`to`로 움직이며 `look_from`→`look_to`를 바라본다. 세로 화면이라 가로 화각이 좁다: lens 35에서 가로 약 32도, 28에서 약 40도, 22에서 약 49도.
- 인물: `who`(cast id, 기본 `resident`), `at`(기본 `[0,0,0]`, 보도 위는 z=0.15), `heading`(기본 0), `actions`. 같은 cast를 한 샷에 여러 번 세워도 된다.
- 동작: `{do, t0, t1, ...}`. t0·t1은 **샷 시작에서 센 초**다. t0 기본 0, t1 기본은 샷 길이.

동작

| do | 하는 일 | 추가 값 |
|---|---|---|
| `idle` | 숨 쉬듯 미세하게 위아래·좌우 | |
| `walk` | 지금 자리에서 `to`까지 일정한 속도로 걷는다(초당 1.8걸음). 걷는 방향으로 몸을 돌리고 끝난 뒤 그 방향을 유지한다 | `to: [x, y]` |
| `reach` | t0~t1 동안 오른팔을 앞으로 80도 들고 상체를 12도 숙인다. 그 뒤 유지 | |
| `bow` | 상체를 35도 숙였다가(가운데 시점) 다시 편다 | |
| `nod` | 고개를 22도 숙였다가 든다(한 번) | |
| `point` | t0~t1 동안 오른팔을 앞으로 90도 들어 가리킨다. 그 뒤 유지 | |
| `shrug` | 어깨를 한 번 으쓱한다 | |
| `sit` | 앉는다(골반 높이 0.55 m, 무릎 90도). t0가 0이면 샷 처음부터 앉아 있고, 0보다 크면 t0에서 6프레임 동안 앉는다. 일어나지 않는다 | |
| `glow` | 몸(눈·머리 제외)이 color로 빛나고 몸 안 점광이 주변을 밝힌다. t0~t1 동안 0에서 strength까지 밝아지고 그 뒤 유지. 바로 켜려면 t1 = t0 + 0.01 | `color`(기본 `#ffe27a`), `strength`(기본 25. 예제는 22. 가까운 컷 25, 넓은 부감 40까지 써 봤다) |

- reach·point는 인물 자신의 오른팔이다(카메라를 보고 서 있으면 화면 왼쪽 팔).
- 같은 관절을 쓰는 동작은 시간을 겹치지 않는다. 상체: idle·reach·bow. 몸 높이: idle·sit. 오른팔: walk·reach·point. 다리: walk·sit. 겹치면 키가 섞여 자세가 튄다.
- 빛나는 정도: 몸 발광 세기 = strength × 0.08, 몸 안 점광 = strength × 30 W.

소품 (`props`, 샷마다 따로 적는다)

| kind | 모양 | 값(기본값) |
|---|---|---|
| `sign` | 기둥 달린 팻말. 판 1.3×0.8 m, 판 가운데 높이 1.7 m. 글자는 판에 맞춰 자동으로 줄어든다 | `text`("안내", 줄바꿈 `\n`), `board`(#1f6b3a), `ink`(#ffffff), `at`, `heading`, `pop_at`(샷 시작에서 센 초. 주면 그때 튀어나오듯 커진다) |
| `box` | 상자 | `size`([0.5, 0.5, 0.5]), `color`(#8b5a2b), `at` |

|---|---|---|
| `room` | `seed`, `ceiling`(기본 true) | 바닥 x -3~3, y -3~2.8. 벽 높이 2.7 m(뒷벽 y=2.85, 좌우벽 x=±3.05), 앞(-Y)은 열려 있다. 천장(그림자를 만들지 않아 해·하늘 빛은 그대로 든다. 위에서 내려다볼 때만 `ceiling: false`). 책상 (-0.6, 2.4) 상판 0.75 m, 모니터·휴대폰, 콘센트와 충전기 (-0.6, 2.75, 높이 1.0) 녹색 불, 의자 (0.6, 1.4) 좌판 약 0.48 m, 침대 (2.3, -0.8), 선반 (-1.8, 2.75, 높이 1.6), 스탠드 (2.3, 2.2), 왼벽 문 (y=0.2), 뒷벽 창 (x=1.6), 천장 조명 (0, 0, 2.6) |

### 고치는 순서

1. 음성 길이를 잰다. `ffprobe -v error -show_entries format=duration -of csv=p=0 narration.wav`. 마지막 샷의 end를 이 길이 이상으로 잡는다.
2. 자막 구간을 잡는다. 시각이 따로 없으면 `ffmpeg -i narration.wav -af silencedetect=noise=-35dB:d=0.25 -f null -`의 `silence_end`~다음 `silence_start`가 말하는 구간이다. 문장을 나눠 `captions`에 넣고 끝맺음 문장은 `notice.closing`과 `closing_start`로 뺀다.
3. `notice`의 배지(가상의 수칙 번호)와 제목을 쓴다.
4. 샷 표(0단계)대로 `shots`를 쓴다. 장소마다 `set`, 같은 장소 다른 각도·시간대는 `reuse_set`.
5. 샷마다 카메라·인물·동작·소품을 넣는다. 1~3단계를 돌려 시트를 보고 좌표·lens를 고친다.
6. 4~5단계로 마무리한다.

## 6. 중간 검수

1. **3단계 시트에서 본다.**
   - 인물·팻말이 세로 화면 밖으로 잘리지 않았는지, 빌딩·신호등 기둥·가구에 가리지 않았는지.
   - 발이 바닥에 붙어 있는지(보도 위는 0.15 m). 앉은 인물이 의자에 맞는지.
   - 빛나는 인물이 얼굴(눈)까지 읽히는지, 바닥에 이상한 빛 무늬가 없는지.
   - 자세 동작(sit)이 t0 전에 미리 나와 있지 않은지(앞 스틸).
   - 왼쪽 위 배지·제목 자리와 아래 자막 자리(아래 400px 위)에 인물 얼굴이 오지 않는지. 5단계 전 스틸에는 글자가 없으니 자리를 어림해서 본다.
2. 타임라인을 고쳤으면 1단계부터 다시 한다(1~3단계는 예제 기준 10초 안쪽).
3. **5단계 뒤** 자막·끝맺음이 나오는 시각으로 한 장씩 뽑아 글자 깨짐·줄바꿈·가림을 본다.
   ```bash
   ffmpeg -ss 4.5 -i out.mp4 -frames:v 1 check_sub.png
   ffmpeg -ss 10.8 -i out.mp4 -frames:v 1 check_closing.png
   ```

## 7. 함정

실제로 만들면서 겪은 것만 적는다.

- **몸 안 점광에 그림자를 켜면 바닥에 이상한 무늬가 생겼다.** 빛이 몸 틈새로만 새어 나가 S자 얼룩이 졌다. 점광은 `use_shadow = False`.
- **점광이 자기 몸까지 비추면 광원 가까운 팔만 하얗게 날고 몸통은 칙칙했다.** 라이트 링킹으로 점광이 자기 몸을 비추지 않게 했다(5.2.3 EEVEE에서 동작 확인). 몸 발광은 형태가 남을 만큼만(strength × 0.08), 눈과 머리는 빛내지 않아야 얼굴이 읽힌다.
- **각진 상자 몸통은 빛날 때 납작한 판처럼 보였다.** 몸통을 둥근 상자로 바꿨다.
- **방에 천장이 없을 때 낮(day) 컷 위쪽에 하늘색이 그대로 보였다.** 천장을 넣고 그림자는 끄게 했다. 카메라를 방 앞 3 m 밖으로 빼면 천장 앞 모서리와 그 위 하늘이 보인다.
- **끝맺음 흰 글자가 횡단보도 흰 줄 위에서 덜 읽혔다.** 외곽선을 두껍게 하고 흐림을 넣었다.
- **거리 컷에서 빌딩이 인물을 가렸고, 걸어오는 경찰이 화면 밖에 있었다.** 빌딩은 보도(5.5~10.5)를 비우고 \|x\|·\|y\| ≥ 10에만 둔다. 세로 화면이라 가로가 좁아 lens를 28로 줄이고 바라볼 점을 옮겼다. 부감 컷 아래가 검게 빈 것도 구도를 다시 잡아 고쳤다.
- **저녁(evening) 컷이 지나치게 주황색이었다.** 프리셋을 누그러뜨렸다.
- **자세 키가 하나뿐이면 샷 처음부터 그 자세가 된다.** 블렌더는 첫 키 앞을 첫 키 값으로 채운다. sit에 t0를 주어도 샷 처음부터 앉아 있어서, t0 > 0이면 선 자세 키를 먼저 넣게 고쳤다. 새 동작도 t0에 기본 자세 키를 먼저 넣는다.
- **sit은 그 자리에서 앉는 동작이다.** t0 전 서 있는 동안 다리가 의자 좌판과 겹쳐 보인다. 앉아 있는 장면이면 t0 0으로 처음부터 앉혀 둔다.
- **블렌더 5.x는 새 키의 보간 설정을 `keyframe_insert`에 반영하지 않는다.** 5.2.3에서 CONSTANT로 두어도 BEZIER 키가 생겨, 숨겨 둔 인물이 제때 나타나지 않고 화면이 서서히 어두워졌다. 스크립트의 `key()`는 넣은 키의 보간을 직접 고친다. 노드 소켓 키는 노드 트리의 애니메이션에 붙는다.
- **5.x에는 `Action.fcurves`가 없다.** F-커브는 `action.layers[].strips[].channelbags[].fcurves`에 있다.
- **time 오타가 조용히 낮으로 바뀌었다.** 지금은 `"Night"`처럼 틀리면 `ValueError`로 멈춘다. 동작의 t1을 빼면 1초로 잡히던 것도 샷 끝까지로 바꿨다(복셀 팩과 같은 규칙).
- **`finish.py`에 `--timeline`을 빼면 예제 안내 틀과 자막이 들어간다.**
- **블렌더는 `--python` 스크립트가 예외로 멈춰도 `--python-exit-code 1`이 없으면 종료 코드 0으로 끝난다.** 5.2.3에서 확인: 붙이면 1, 빼면 0. 그래도 로그 끝의 `Traceback`과 `SCENE_OK`·`RENDER_COMPLETE` 줄, 결과 파일을 직접 본다.
- 5.2.3 로그의 `World.use_nodes` DeprecationWarning은 결과에 영향이 없다.
- `render-manifest.json`과 `frames/_signature.txt`에는 PC 경로가 들어가지 않지만, .blend에는 팻말 글꼴 파일 경로가 남는다. 남에게 넘길 때는 .blend와 렌더 산출물을 빼고 팩만 넘긴다.

## 8. 실측 시간

시험 환경: Windows 10, RTX 3070 Ti 8GB, Blender 5.2.3 LTS, 공통 예제 대본(1080×1920, 24fps, 15초, 360프레임).

| 단계 | 시간 |
|---|---|
| 장면 만들기(`create_psa.py`) | 1초 |
| 스틸 4장(50%, 16샘플) | 3초 |

- 음성·배경음 합성은 이전 예제(12초)에서 시험 음(10초 내레이션 자리 + 12초 배경음)으로 확인했다: 길이가 영상과 같고, AAC 48kHz 스테레오, 내레이션이 끝난 뒤에도 배경음이 남는다.

확인하지 못한 것
- Blender 4.5 LTS에서의 실행과 라이트 링킹.
- macOS·리눅스, 그래픽 카드 없는 PC.
- street_night 세트를 day·evening으로 쓴 모습, 1분이 넘는 타임라인, 한 샷에 인물 9명 이상.
- 실제 안내 방송 말투 TTS를 넣었을 때의 자막 싱크.

동작 시험(예제 밖, 2026-11-10): 방 낮(day)에서 point·shrug·nod·bow·reach, sit(t0 1.0), 의상 coat·hoodie, `eyes: false`, 소품 box·cone을 스틸로 확인했다.

## 9. 완료 기준

```bash
ffprobe -v error -show_entries stream=codec_type,codec_name,width,height,r_frame_rate,duration -of compact out.mp4
```

- 비디오: h264, 1080×1920, 24fps.
- 길이: 마지막 샷 end와 같다(예제 15.000초, 360프레임).
- 오디오: aac 트랙이 있고 길이가 영상과 같다. `--audio`를 줬다면 내레이션이 들리고 `--music`을 줬다면 배경음이 섞여 있다.
- 검수 시트와 자막·끝맺음 스틸을 직접 봤다: 잘림, 가림, 발 뜸, 바닥 빛 무늬, t0 전 자세, 얼굴 위 글자가 없다.
- 배지·제목에 실제 기관 이름이나 로고가 없다.
- 사용자에게 보고한다: 결과 영상 경로, 단계별 시간, 확인하지 못한 것, 남은 어색한 장면.

자세한 내용은 `LICENSES.md`.

- 블렌더로 만든 그림·영상·.blend 파일은 만든 사람의 것이다.
- 외부 3D 모델·텍스처·HDRI 같은 외부 소재는 쓰지 않았다. 모든 형태는 코드로 만든 도형이다.
- 팩에는 글꼴 파일이 없다. Noto Sans KR은 SIL OFL 1.1, 맑은 고딕은 Windows 글꼴 라이선스를 따른다. 팻말 글자는 이 글꼴 모양으로 영상에 들어간다. 조건이 분명해야 하면 Noto Sans KR을 쓴다.
- 음성·배경음은 팩에 없다. 사용자가 준비하고 사용 권리를 직접 확인한다.
- 참고한 인스타그램 연작은 화면 구성과 대본 공식만 참고했다. 그 계정의 캐릭터·제목·대본·영상·음성은 팩에 없다. 실제 공공기관을 흉내 내지 않는다.
- `bpy`를 쓰는 스크립트를 외부에 공개 배포할 때는 GNU GPL 호환 조건을 따라야 한다는 것이 블렌더 재단 안내다.

## 11. 쓰지 않는 것

영상 생성 AI, 이미지 생성 AI, 외부 유료 API를 쓰지 않는다. 내려받아야 하는 3D 에셋이나 텍스처도 쓰지 않는다. 모든 형태와 재질은 블렌더 내장 파이썬 코드로 만들고 ffmpeg로 마무리한다.
