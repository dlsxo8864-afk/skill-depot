# 리모션 키네틱 타이포 영상 (llmvid-remotion-kinetic)

검증된 예제와 절차를 묶은 팩이다. 버튼 하나로 끝나는 자동 도구가 아니다. `example/` 의 코드를 새 대본에 맞게 고쳐 쓰고, 스틸을 눈으로 보며 다듬는다.

```
llmvid-remotion-kinetic/
  SKILL.md        이 문서
  LICENSES.md     라이선스
  example/        공통 예제 대본을 실제로 만든 Remotion 프로젝트
    package.json  remotion.config.ts  tsconfig.json
    src/          index.ts  Root.tsx  Kinetic.tsx  fonts.ts  script.ts  script.json
    public/fonts/ BlackHanSans-Regular.ttf  OFL-BlackHanSans.txt
```

## 1. 이 스킬이 만드는 것

대본을 **글자만으로 된 세로 영상**(1080×1920, 24fps, MP4)으로 만든다. 말하는 덩어리마다 큰 글자가 단색 바탕 위에 튀어나오고(스프링), 덩어리가 바뀔 때 바탕색이 바뀐다. 강조할 줄은 다른 색으로 흔들린다. 그림과 인물은 없다.

예제(`example/`)는 공통 예제 대본 「점심 메뉴 정하는 법」 15초(360프레임)다. 같은 묶음의 다른 팩도 모두 이 대본을 쓰고, 팩마다 화풍과 연출만 다르다. 글자 덩어리는 대본에서 자동으로 만들어진다(예제 8개).

**잘 맞는 대본**
- 말맛이 중요한 짧은 썰, 한 줄 훅, 대사 위주의 이야기.
- 음성(내레이션)이 있는 영상. 글자가 음성을 따라가며 뜬다.

**안 맞는 대본(한계)**
- **보여 줄 것이 있는 대본에는 안 맞는다.** 인물, 제품, 장소, 화면 캡처는 나오지 않는다. 글자와 바탕색뿐이다.
- 따로 자막 줄이 없다. 큰 글자가 곧 자막이다. 한 덩어리에 긴 문장을 다 넣을 수 없어서 대본을 짧게 끊어야 한다.
- 음성이 없으면 글자가 뜨는 박자를 어림으로 잡아야 해서 어색해지기 쉽다.
- 움직임은 한 가지(아래에서 튀어 오르기)다. 글자가 날아다니거나 한 글자씩 뜨는 연출은 코드를 새로 써야 한다.

## 2. 입력

사용자에게 받을 것:

1. **대본** — 15~30초 안팎. 말하는 순서대로 적힌 글.
2. **음성 파일**(wav/mp3) — 없어도 된다. 없으면 소리 없는 영상이 나온다.
3. **자막 타이밍** — 문장(덩어리)마다 시작·끝 초. 없으면 음성에서 쉬는 구간을 찾아 잡는다(4절 4단계).
   음성도 타이밍도 없으면 1초에 4~5자쯤으로 어림해 잡고(이전 예제 음성은 29.5초에 132자, 1초에 4.5자였다), 어림값이라고 사용자에게 알린다.
4. **저장 폴더** — 결과 MP4 를 둘 곳.

## 3. 먼저 확인할 환경

| 필요한 것 | 확인 명령 | 비고 |
|---|---|---|
| Node.js | `node -v` | `package.json` 의 조건은 20.19 이상의 20.x, 22.13 이상의 22.x, 또는 24 이상. 시험은 v22.14.0 |
| npm | `npm -v` | 처음 한 번 `npm install` 에 쓴다 |
| ffmpeg · ffprobe | `ffmpeg -version` | 효과음 합성, 음성 구간 찾기, 결과 확인에 쓴다. 시험은 8.1.1 |

- 없는 것이 있으면 **설치하지 말고 사용자에게 먼저 묻는다.**
- `npm install` 은 패키지를 내려받는다(수백 MB). **사용자가 허락한 뒤** 처음 한 번만 한다.
- Remotion 은 렌더할 때 Chrome Headless Shell 을 쓴다. 없으면 첫 렌더 때 내려받으려 하므로 이것도 사용자에게 미리 알린다. (시험 PC에는 이미 받아져 있어서 내려받는 과정은 확인하지 못했다.)
- Remotion Studio(`npm run dev`)는 쓰지 않아도 된다. 이 스킬은 스틸을 뽑아 눈으로 보는 방식으로 검수한다.

## 4. 절차

모든 명령은 `example/` 을 복사한 작업 폴더 안에서 실행한다. 경로는 그 폴더 기준 상대 경로다.

1. **예제를 작업 폴더로 복사한다.** 팩의 `example/` 폴더를 통째로 사용자가 정한 작업 폴더에 복사한다(팩 원본은 그대로 둔다).
2. **패키지를 받는다(처음 한 번, 사용자 허가 뒤).**
   ```
   npm install
   ```
3. **고치기 전에 예제가 도는지 본다.** 스틸 한 장을 뽑아 직접 연다.
   ```
   npx remotion still src/index.ts Kinetic out/check_0040.png --frame=40
   ```
   `<컴포지션>` 자리는 `Kinetic`, 그다음은 저장할 PNG, `--frame` 은 0부터 세는 프레임 번호다.
4. **타이밍을 잡는다.** 사용자가 준 자막 타이밍이 있으면 그대로 쓴다. 없고 음성만 있으면 쉬는 구간을 찾는다.
   ```
   ffmpeg -hide_banner -i public/audio/narration.wav -af silencedetect=noise=-35dB:d=0.15 -f null -
   ```
   `silence_start` / `silence_end` 가 찍힌다. 말 덩어리는 한 `silence_end` 부터 다음 `silence_start` 까지다. 이것으로 덩어리의 시작·끝 초를 정한다. (이전 예제 음성에서 돌려 보았고 숨 쉬는 곳마다 구간이 잡혔다. 소리가 작은 음성은 `-35dB` 를 조절한다.)
5. **음성을 넣는다(있을 때).** 파일을 `public/audio/narration.wav` 로 복사하고 `src/Kinetic.tsx` 의 상수를 바꾼다.
   ```ts
   const NARRATION: string | null = 'audio/narration.wav';
   ```
   `null` 로 두면 소리 없이 렌더된다. mp3 도 같은 방법으로 쓴다(시험은 wav 로만 했다).
6. **대본에 맞춰 코드를 고친다.** 5절을 따른다.
7. **타입 검사.**
   ```
   npx tsc --noEmit
   ```
8. **스틸로 검수한다.** 6절을 따른다. 고치고 다시 뽑기를 되풀이한다.
9. **소리를 넣었다면 앞 3초만 렌더해 소리가 들어갔는지 본다.**
   ```
   npx remotion render src/index.ts Kinetic out/head.mp4 --frames=0-71
   ```
10. **최종 렌더.**
    ```
    npx remotion render src/index.ts Kinetic out/final.mp4
    ```
11. **결과를 확인하고 알린다.** 9절을 따른다.

### 효과음(선택)

팩에는 소리 파일이 없다. 메시지를 보내는 '톡' 소리가 필요하면 ffmpeg 로 직접 만든다(내려받지 않는다).

```
ffmpeg -y -f lavfi -i "aevalsrc='0.5*sin(2*PI*(900+2400*t)*t)*exp(-26*t)':s=48000:d=0.25" -ac 2 public/audio/send.wav
```

- 0.25초, 48kHz, 위로 올라가며 빨리 사라지는 소리다. 시험 PC에서 파일이 만들어지고 영상에 섞여 들어가는 것까지 확인했다. 음색이 마음에 드는지는 사람이 들어 봐야 한다.
- 숫자를 바꿔 다른 소리를 만든다: `900` 시작 높이, `2400` 올라가는 빠르기, `26` 사라지는 빠르기, `d` 길이.
- 만든 뒤 `src/Kinetic.tsx` 의 `SFX_SEND` 를 `'audio/send.wav'` 로 바꾼다. 소리가 나는 때는 `script.json` 의 `sfx.send`(초)다.

## 5. 대본에 맞춰 고칠 곳

대본과 연출을 나눠 두었다. 컴포지션 파일 안에는 대사도 프레임 번호도 없다.

| 파일 | 담긴 것 | 새 대본에서 |
|---|---|---|
| `src/script.json` | 대본. 길이(`seconds`, `frames`), 등장인물(`cast`), 단톡방 이름, 구간(`beats`)마다 시작·끝 초, 내레이션, 키워드, 대화(`chat`: 초, 누구, 문구), 시계(`clock`), 눈금(`gauge`), 도장(`stamp`), 결과(`result`), 자막(`subs`), 효과음 시각(`sfx`) | 새로 쓴다 |
| `src/script.ts` | 대본을 읽어 `S`, `CHAT`, `SUBS`, `SFX`, `beat()`, `fr()` 같은 값으로 내놓는다 | 고치지 않는다 |
| `src/Kinetic.tsx` 의 `[풀이]` | `PALETTE`(구간마다 바탕색·글자색·강조색), `MAX_LINE`(한 줄 글자 수, 7), `LINES_PER_CHUNK`(한 번에 보이는 줄 수, 2) | 화면 느낌을 바꿀 때 |
| `src/Kinetic.tsx` 의 `NARRATION`, `SFX_SEND` | 음성·효과음 파일(`public/` 기준 경로) 또는 `null` | 소리를 넣을 때 |

글자 덩어리는 대본에서 자동으로 만들어진다.

- 구간의 내레이션(`narration`)을 낱말 단위로 줄에 담는다. 한 줄이 `MAX_LINE` 자를 넘으면 다음 줄로 넘긴다.
- 줄을 `LINES_PER_CHUNK` 줄씩 묶어 한 덩어리로 보여 준다. 덩어리가 뜨는 때는 그 구간 자막(`subs`)의 시작~끝 사이를 글자 수 비율로 나눈 값이다.
- 강조색으로 흔들리는 줄: 구간 키워드(`keyword`)가 든 줄. 없으면 그 구간의 마지막 줄.
- 화면 위쪽에는 구간 키워드 칩이 뜬다. 바탕색은 구간마다 `PALETTE` 순서대로 바뀐다.
- 글자 크기는 줄 길이로 정해진다: 4자 이하 260px, 6자 이하 190px, 그보다 길면 138px.

줄이 어색하게 끊기면 내레이션의 띄어쓰기를 고치거나 `MAX_LINE` 을 바꾼다. 한 낱말이 `MAX_LINE` 보다 길면 그 낱말만 한 줄이 된다(예제의 "김치찌개입니다.").

고치는 순서

1. 음성 길이를 재서 `seconds`(올림)와 `frames`(초 × 24)를 정한다. `Root.tsx` 는 이 값을 읽는다.
2. 구간(`beats`)을 나누고 구간마다 `start`·`end`(초), 내레이션, 키워드, 화면에 보일 것을 쓴다. 구간 경계는 말이 쉬는 곳에 둔다.
3. 자막(`subs`)을 음성에 맞춘다. 한 줄 12자 이하, 줄바꿈은 `\\N`, 두 줄까지. 자막끼리 시간이 겹치지 않게 한다.
4. `sfx`(전송·알림·도장 초)를 대화 시각에 맞춘다.
5. `npx tsc --noEmit` 으로 타입을 검사하고 스틸로 본다(6절).

## 6. 중간 검수

최종 렌더 전에 스틸을 뽑아 **직접 눈으로 본다.** 코드만 읽고 넘어가지 않는다.

```
npx remotion still src/index.ts Kinetic out/s_0090.png --frame=90
```

덩어리마다 한 장씩 보는 것이 가장 확실하다. 구간마다 앞·가운데·끝 프레임을 한 장씩 뽑으면 된다. 줄이 긴 덩어리는 꼭 본다. 예제에서 쓸 만한 프레임: 24, 66, 110, 136, 180, 230, 300, 340.

볼 것:

- 한글이 깨지지 않았는가(네모, 물음표, 엉뚱한 글꼴).
- 글자가 화면이나 상자 밖으로 넘치지 않는가.
- 빈 화면이 없는가.
- 화면의 글자가 그 시각의 음성(대본)과 맞는가.

## 7. 함정

- **`b` 는 쓰이지 않는다.** 덩어리를 일찍 지우려고 `b` 를 고쳐도 화면은 그대로다. 다음 덩어리의 `a` 를 고친다.
- **`hi` 는 줄과 글자가 완전히 같아야 한다.** 마침표 하나만 달라도 강조되지 않는다(오류도 나지 않는다).
- 본문 글꼴(`KR`)은 이 템플릿에서 쓰지 않는다. 글자는 모두 Black Han Sans(`Head`)다. 그래도 `fonts.ts` 가 본문 글꼴을 찾아보기 때문에 아래의 404 줄은 똑같이 찍힌다. 한자·이모지·드문 특수문자처럼 Black Han Sans 에 없을 수 있는 글자는 시험하지 않았다. 쓰게 되면 스틸로 확인한다.
- **`CaptionKR-Bold.ttf` 404 줄은 오류가 아니다.** 렌더할 때 `…/public/fonts/CaptionKR-Bold.ttf  Failed to load resource: 404` 가 빨간 글씨로 여러 번 찍힌다(스틸은 2번, 72프레임 렌더는 9번). 본문 글꼴 파일이 팩에 없어서 시스템 글꼴로 넘어갔다는 뜻이고 렌더는 정상으로 끝난다. 시험 PC에서는 Noto Sans KR Bold 와 맑은 고딕 Bold 두 경우 모두 한글이 제대로 그려졌다.
- **한글이 가늘게 나오고 숫자가 명조체로 나오면** 본문 글꼴을 못 찾은 것이다. 이때 터미널에 `[fonts] 본문 글꼴(파일·시스템 글꼴)을 찾지 못했다` 가 찍히고 렌더는 멈추지 않는다(시험에서 확인). `src/fonts.ts` 의 `BODY_LOCAL` 목록에 그 PC에 있는 한글 글꼴 이름을 더하거나, 한글 글꼴 파일을 `public/fonts/CaptionKR-Bold.ttf` 로 둔다(사용자에게 물어본 뒤). macOS·리눅스 후보는 목록에 넣어 두었지만 확인하지 못했다.
- **새 컴포지션 파일을 만들면 `import './fonts';` 를 넣는다.** 원본에서는 한 파일이 다른 파일의 글꼴 로드에 기대고 있었다. 빠지면 그 파일만 따로 렌더할 때 글꼴이 기본 글꼴로 나온다.
- **`node_modules` 는 결과물과 함께 묶거나 옮기지 않는다.** 필요하면 그 자리에서 `npm install` 로 다시 만든다.
- 렌더 결과는 같은 이름이면 덮어쓴다(`remotion.config.ts` 의 `setOverwriteOutput(true)`).

## 8. 실측 시간

시험 환경: RTX 3070 Ti 8GB, Windows 10, Node 22.14.0, Remotion 4.0.540. 명령을 실행해서 끝날 때까지(번들 시간 포함)다. 소리 없이 쟀다.

| 작업 | 걸린 시간 |
|---|---|
| 타입 검사(`npx tsc --noEmit`) | 몇 초 |
| 15초 전체(360프레임) 렌더 | 14초 |

스틸 한 장(`remotion still`)은 이전 예제에서 6~10초였다. 이번 대본으로는 따로 재지 않았다.

## 9. 완료 기준

1. `npx tsc --noEmit` 이 오류 없이 끝난다.
2. 컷마다 스틸을 한 장 이상 직접 보고 글자·그림을 확인했다.
3. 결과 MP4 를 `ffprobe` 로 확인한다.

```
ffprobe -v error -show_entries stream=codec_type,codec_name,width,height,r_frame_rate,duration -of default=nw=1 out/final.mp4
```

   - 영상: 1080×1920, 24fps, 길이가 대본 길이(예제는 15초)와 맞는가.
   - 소리: 음성을 넣었다면 오디오 스트림이 있고 무음이 아닌가.
     `ffmpeg -i out/final.mp4 -af volumedetect -f null -` 의 `mean_volume` 이 -60dB 보다 훨씬 크면 소리가 있는 것이다.
     `NARRATION` 과 `SFX_SEND` 가 둘 다 `null` 이면 MP4 에 오디오 스트림이 아예 없다(시험에서 확인). 올릴 곳이 소리 트랙을 요구하면 사용자에게 알린다.
4. 사용자에게 **결과 경로, 걸린 시간, 남은 문제**(어림으로 잡은 타이밍, 확인 못 한 것)를 알린다.

## 10. 라이선스 (자세한 것은 `LICENSES.md`)

- **Remotion**: 개인, 비영리, 직원 3명 이하 영리 회사는 무료. **직원 4명 이상인 영리 회사는 유료 회사 라이선스가 필요하다.** 회사 일로 쓰는 것 같으면 렌더하기 전에 사용자에게 알린다.
- **Black Han Sans**(제목 글꼴, 팩에 들어 있음): SIL OFL 1.1. 영상에 써도 된다.
- **본문 글꼴**: 팩에 없다. PC에 깔린 Noto Sans KR(OFL)이나 맑은 고딕(Windows 에 딸린 글꼴)을 쓴다. 글꼴 파일을 프로젝트에 복사해 남에게 넘길 때는 그 글꼴의 라이선스를 확인한다.
- **음성·효과음**: 팩에 없다. 음성의 권리는 가져온 사람이 확인한다. 효과음은 ffmpeg 로 직접 만든 소리다.

## 11. 쓰지 않는 것

영상 생성 AI, 이미지 생성 AI, 유료 API, 외부 그림·영상 소재. 화면에 보이는 것은 모두 코드로 그린다.
