# 직장 썰 · 씨댄스 제작

원문에서 핵심 사건을 골라 1인칭 나레이션과 영상 소스를 준비한다. 이름·회사·지명·세부 신상은 제거하거나 가상 설정으로 바꾸고, 원문 요약과 각색 대본은 별도로 보관한다. 겹친 캡처는 합치고 사용자가 지정한 단락만 사용한다.

## 이 시리즈의 제작 기준

- 기본 목표는 9:16, **30초 이내**. 더 짧아도 된다. 글자 수나 프롬프트 타임코드만으로 발화시간을 확정하지 않는다.
- 원문에 없는 결과·폭력·강요·보복을 조회수 훅으로 추가하지 않는다. 인물의 추측은 추측으로 남긴다. 훅은 실제 낭독 대본 첫 문장에도 포함한다.
- 생성 영상은 외부 나레이션용 소스다. 무음 설정이 있으면 사용하고, 없으면 최종 편집에서 원음을 제외한다. 인물에게 대사를 립싱크시키지 않는다.
- 영상 재생 중에는 **실제 발화 자막만** 넣는다. 제목·EP·시리즈명·고정 안내 문구는 별도 썸네일에만 둔다.
- 사진/영상 생성에 글자·말풍선·로고·워터마크를 요청하지 않는다. 화면·사원증·문서의 읽을 수 있는 글자는 제외한다.
- 썸네일은 글자 없는 승인 사진과 artifact-template-1의 네이티브 타이포그래피를 분리한다. 완성PNG를 AI로 반복 재편집하지 않는다. 다른 디자인을 사용자가 지정하면 그 선택을 따른다.

## 업로드용 멘션 메모 (EP3부터)

- EP3부터 각 회차의 기본 납품물에 `EP{번호}-게시글-멘션.txt`를 포함한다. 영상·썸네일과 같은 회차 폴더에 UTF-8로 저장하고, 구글드라이브 납품이 승인된 작업이면 같은 Drive 회차 폴더에도 함께 올린다.
- 회차마다 **서로 다른 말맛의 3안**을 준비한다. 가볍게 묻는 형, 친구와 공감하는 형, 농담 섞는 형 등을 사건 분위기에 맞춰 구분한다. 같은 문장의 단어만 바꾸는 세 안으로 채우지 않는다.
- 각 안의 본문은 짧은 두 줄. 친구에게 썰을 푸는 듯 친근하고 가볍게 쓰고, 공감 질문과 시청자의 경험·사례를 자연스럽게 끌어낸다. “경험을 공유해주세요”, “댓글로 들려주세요” 같은 설문·공지 말투를 반복하지 않는다. 짧은 ㅋㅋ·말줄임표·이모지는 필요할 때만 사용한다.
- 회차의 구체적인 상황을 살려 쓰되 원문에 없는 피해나 결과를 사실처럼 추가하지 않는다. 농담이나 가정은 농담·가정으로 읽히게 쓴다.
- 각 안의 본문 뒤 빈 줄에 해시태그 2~3개를 한 줄로 넣는다. 이 직장 썰 시리즈는 `#회사썰`을 기본으로 하고 나머지는 회차 주제에 맞춘다.
- 한 메모에서 `[A안 · 유형]` / `[B안 · 유형]` / `[C안 · 유형]`으로만 구분한다. 각 구분 아래는 바로 복사할 본문 두 줄과 해시태그만 두고 작성 설명·EP 제목·코드 블록은 덧붙이지 않는다. 이 문구를 영상 재생 중 자막이나 고정 문구로 삽입하지 않는다.
- 기획 중에는 초안으로 준비하고 최종 대본에 맞춰 확정한다. 납품 완료 전 3안 존재, 각 본문 두 줄, 안별 해시태그 개수와 회차 폴더를 확인한다.

## 제작 흐름

두 제작 패키지를 참고할 때는 [사례 검증](references/case-studies.md)을 먼저 읽는다. 보고서·검수 이미지도 실제 승인 MP4의 해시와 장면에 맞는지 대조한다. 계획, 실행 요청, 실제 출력, 사용자 승인과 후반 수정은 다른 기록이다.

1. 기존 회차의 확정 대본·인물 시트·영상이 있으면 먼저 확인한다. 완료 회차의 대본이나 모델명을 추측해 덮어쓰지 않는다.
2. 제목 두 줄, 훅 포함 나레이션, 감정 지시, 장면표, 복사 가능한 전체 영상 프롬프트, 글자 없는 썸네일 사진 프롬프트를 제공한다. 전체 프롬프트에는 전역 설정뿐 아니라 **각 컷의 시간·프레이밍·행동**도 포함한다.
3. 인물마다 승인된 기준 얼굴 한 장을 정하고, 표정·전신·의상은 그 기준에서 각각 독립 파생한다. 연쇄 재생성으로 배우를 바꾸지 않는다. 시트는 일반 편집으로 조립한다. 글자가 정리된 무인 공간 플레이트와 얼굴·의상 참조를 역할별로 결속한다. 한 컷에 작고 보이는 행동 하나를 둔다. 반복 끄덕임, 가슴 튕김, 과도한 삼킴, 손 떨림, 사원증 만지작거림을 기본 감정 표현으로 쓰지 않는다.
   - 유닛마다 카메라·문·거울·이동 목적지, 인물 시선과 소품 소유권·수량을 확인한다. 렌즈는 공간·거리·센서·크롭에 맞춘다. 다른 장소/의상은 복잡도에 따라 유닛으로 분리하되 모든 30초를 무조건 여러 호출로 만들지는 않는다.
4. 음성을 생성하는 작업이면 먼저 샘플을 실측해 문장·쉼을 조정한다. 최종WAV 기준으로 자막을 정렬하고 인용 대사도 화자 지시와 구분한다. 음성 길이를 글자 수 계산으로 대체하지 않는다.
5. 영상 생성 또는 업로드 경로는 아래를 따른다. 생성 프롬프트의 시간은 연출 목표이며 프레임 싱크 보장이 아니다.
6. 들어온 원본은 보존하고 메타데이터·장면 순서·신체 동작·역할·글자 노출을 확인한다. 문제가 있는 구간만 편집 결정표(EDL)로 조정한다. 실제 사례와 판단 기준은 [production-guide.md](references/production-guide.md) 및 [case-studies.md](references/case-studies.md)를 읽는다.
7. 편집 시 승인 음성, 실제 자막 타임코드, 소스 인/아웃 프레임, 재생률을 Remotion에 넘긴다. 기존 출력은 1080×1920/24fps이며 새 소스의 fps를 먼저 확인해 변환한다. 전체 30초·마지막 발화·한글·얼굴가림·결함컷을 검수한 뒤 완료로 표시한다.

## 수동 / API 경로

- **수동**: 프롬프트와 인물 참조 제공 → 사용자가 생성한 MP4 업로드 → 소스 검수 → Remotion. 외부 제작 영상을 받았다고 새 생성 작업을 시작하지 않는다.
- **API**: 요청된 제공자를 우선하고 실행 시 최신 공식 스키마·가격을 확인한다. 현재 검증한 어댑터는 `bytedance/seedance-2.5/us/reference-to-video`다. `aspect_ratio: 9:16`, `resolution: 1080p`, `generate_audio: false`, `codec: H264`, `task: reference`, `duration: "4".."30"`을 명시한다. Genspark의 `audio_enable`을 그대로 전송하지 않는다. UI 모델명만으로 API ID나 동일 내부 버전을 추정하지 않는다. [API 워크플로우](references/api-workflow.md)를 필요한 경우 읽는다.
- 최대 길이가 30초보다 짧거나 다중 장면 연속 생성이 무너질 경우 장면 단위(유닛)로 분할하고 동일한 인물 마스터 참조를 재사용한다.
- 실제 실행 요청이 있는 범위에서만 유료 생성·외부 업로드를 수행한다. 기획 요청이나 이 스킬을 읽은 것만으로 생성·게시 권한이 생기지 않는다. 현재 대화의 기존 승인은 유지한다.
- 제출 후 반환된 request ID, status_url, response_url을 원본 그대로 저장하고 작업 상태를 조회한다. 응답 지연이나 타임아웃을 이유로 임의 재제출하지 않는다.
- 대시보드의 연결 표시와 실제 로컬 API CLI의 FAL_KEY 설정은 독립적이다. 실제 인증 환경변수 상태를 명확히 구분하여 보고한다.

로컬 도구는 `scripts/seedance_runner.py`로 제공한다. `validate`/`prepare`/`qc`는 오프라인이다. 제출은 기본 dry-run이며 실제 요청에는 `--execute`가 필요하다. 준비 JSON의 생성은 품질 승인이나 유료 실행 승인을 대신하지 않는다. 현재 CLI와 웹 대시보드는 아직 연결되지 않았다. 실제 생성 결과를 비교하기 전에는 API 이식만으로 기존 품질 재현이 검증됐다고 말하지 않는다.
