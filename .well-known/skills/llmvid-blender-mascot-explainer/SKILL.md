# 블렌더 마스코트 설명 영상 (llmvid-blender-mascot-explainer)

검증된 예제와 절차를 묶은 팩이다. 버튼 하나로 끝나는 자동 도구가 아니다.
`example/`은 공통 예제 대본 「점심 메뉴 정하는 법」(15초)을 실제로 만든 것이다. 같은 묶음의 다른 팩도 모두 이 대본을 쓰고, 팩마다 화풍과 연출만 다르다.
새 대본에는 `script.json`(대본)을 새로 쓰고 `plan.py`(이 팩의 풀이)를 맞춘다.

## 1. 이 스킬이 만드는 것

- 짙은 남색 무대와 스포트라이트, 빛나는 원형 단. 그 위에 직접 디자인한 마스코트 한 명(크림색 둥근 머리, 얼굴 화면, 청록 몸, 떠 있는 손).
- 마스코트 머리 위로 화면 카드가 통통 튀며 뜬다: 키워드 칩, 메시지 카드, 단톡 카드(대화가 한 줄씩 는다), 시계(바늘이 돈다) + 눈금 막대(차오른다), 알림 카드(위에서 떨어진다), 결과 카드 + 도장 + 색종이.
- 구간마다 마스코트의 표정(normal, happy, surprised, sleepy)과 동작(wave, point_up, shrug, nod, jump)이 바뀐다.
- 화면 위쪽에 구간마다 바뀌는 제목 띠(흰 알약 + 단계 번호), 아래에 굵은 자막.
- 결과: 1080×1920, 24fps MP4. 예제는 15초(360프레임).
- 외부 3D 소재를 쓰지 않는다. 장면은 블렌더 기본 도형, 글자와 카드는 Pillow로 그린 그림이다.

잘 맞는 대본
- 요령·순서·비교를 설명하는 정보형 쇼츠("~하는 법", "~가 되는 과정").
- 메신저 대화, 시간, 수치, 결과 한 줄처럼 카드로 보여 줄 수 있는 내용.
- 15~40초, 구간 4~6개.

안 맞는 대본
- **사람이 나와 연기하는 이야기.** 등장하는 것은 마스코트 한 명과 카드뿐이다.
- **입 모양 맞춤(립싱크)이나 손가락 연기.** 팔다리 관절이 없고 손은 떠 있는 공이다.
- 실물 제품이나 실제 화면 캡처가 필요한 설명. 카드는 코드로 그린 그림이다.
- 긴 문장. 카드와 말풍선은 줄바꿈을 하지 않는다(한 줄 12자 안팎).

## 2. 입력

| 입력 | 필수 | 설명 |
|---|---|---|
| 대본 | 필수 | 구간마다 내레이션과 화면에 보일 것. `script.json` 형식으로 옮긴다 |
| 음성 파일 | 선택 | wav/mp3. 없으면 소리 없는 영상이 된다 |
| 자막 타이밍 | 선택 | (시작 초, 끝 초, 문구). 없으면 음성에서 구간을 잡는다(5절) |
| 저장 폴더 | 필수 | 작업 폴더. scene.blend, frames/ 약 682MB |

## 3. 먼저 확인할 환경

```
blender --version      # 5.x 에서 만들고 확인했다(5.2.3). PATH 에 없으면 blender 실행 파일 위치를 사용자에게 묻는다
ffmpeg -version        # libx264, libass(subtitles 필터)가 든 빌드
python --version       # 3.10 이상
python -c "import PIL; print(PIL.__version__)"   # Pillow
```

- 없는 것이 있으면 사용자에게 알리고 묻는다. 설치와 내려받기는 허가를 받은 뒤에만 한다.
- 한글 글꼴: `python example/fontfind.py`가 찾은 글꼴을 찍는다. 못 찾으면 사용자에게 글꼴 파일을 받아 `--font`로 넘긴다.
- EEVEE는 그래픽 카드를 쓴다. 시험은 Windows 10 + RTX 3070 Ti에서 `blender -b`(백그라운드)로 했다. 그래픽 카드가 없는 PC나 화면 없는 서버에서는 시험하지 못했다.

## 4. 절차

작업 폴더를 만들고 그 안에서 모든 명령을 돌린다. 스크립트는 **현재 폴더**에 결과를 쓴다.
팩의 `example/`은 그대로 두고 작업 폴더의 `scripts/`로 복사해 그 사본을 고친다.

```
작업 폴더/
  scripts/          example 사본(script.json, plan.py 를 여기서 고친다)
  tex/ overlay/     1단계 결과(장면에 붙일 그림, 영상 위에 얹을 그림)
  scene.blend       2단계 결과
  tests/            3단계 검수 스틸
  frames/           4단계 최종 프레임
  fonts/ subs.ass   5단계가 만드는 중간 파일
  out.mp4           결과
```

**0단계. 대본을 `script.json`으로 쓴다.** `example/script.json`을 본뜬다. 그다음 5절대로 `plan.py`를 맞추고 `python scripts/plan.py`로 읽힌 값을 찍어 본다.

**1단계. 그림을 만든다.**

```
python scripts/cards.py                # [--font 굵은글꼴]
```

`tex/`와 `overlay/`에 PNG가 생긴다. 몇 장을 직접 열어 글자가 깨지거나 넘치지 않았는지 본다.

**2단계. 장면을 조립한다.**

```
blender -b --python-exit-code 1 -P scripts/create_scene.py
```

`scene.blend`가 생긴다. `tex/`가 없으면 "먼저 cards.py"라고 알리고 멈춘다.

**3단계. 스틸로 검수한다(6절).**

```
blender -b scene.blend --python-exit-code 1 -P scripts/render.py -- 30,66,100,140,180,214,236,280,300,326,354 540 960 16 tests/t
python scripts/sheet.py tests/sheet.png tests/t0030.png tests/t0066.png tests/t0100.png tests/t0140.png tests/t0180.png tests/t0214.png tests/t0236.png tests/t0280.png tests/t0300.png tests/t0326.png tests/t0354.png --cols 6
```

인자: `프레임목록 폭 높이 샘플 접두사`. 프레임목록은 `1,5,9` 또는 `a-b:step`.

**4단계. 최종 렌더.** 2분을 넘으므로 백그라운드로 돌린다.

```
blender -b scene.blend --python-exit-code 1 -P scripts/render.py -- 1-360 1080 1920 16 frames/f
```

이미 있는 프레임은 건너뛴다. 끊기면 같은 명령을 다시 돌린다. 진행은 출력의 `FRAME 번호 컷 초` 줄로 본다.

**5단계. 화면 위 그림·자막·효과음을 붙인다.**

```
python scripts/finish.py frames 1 out.mp4 --audio <음성 파일>
```

- `--audio`를 빼면 소리 없는 영상(조용한 오디오 트랙)이 된다.
- 효과음(전송 '톡', 알림 진동, 도장 '쿵')은 `--audio`가 있을 때만 들어간다. `--sfx on`/`off`로 바꿀 수 있다. 전부 ffmpeg로 합성한 소리다.
- 프레임 폴더는 절대 경로로 줘도 된다. `--font`, `--crf`(기본 22)도 있다.

**6단계. 확인한다(9절).**

## 5. 대본에 맞춰 고칠 곳

대본과 풀이를 나눠 두었다. 스크립트 안에는 대사도 프레임 번호도 없다.

| 파일 | 담긴 것 | 새 대본에서 |
|---|---|---|
| `script.json` | 대본. 길이(`seconds`, `frames`), 등장인물(`cast`), 구간(`beats`)마다 내레이션·키워드·대화(`chat`: 초, 누구, 문구), 자막(`subs`), 효과음 시각(`sfx`), 도장(`stamp`), 결과(`result`) | 새로 쓴다 |
| `plan.py`의 `# [풀이]` 블록 | 이 팩이 대본을 그리는 방식(아래 표) | 구간 구성이 달라지면 고친다 |
| `cards.py` | 그림의 생김새 | 카드 모양을 바꿀 때만 |
| `create_scene.py` | 장면의 생김새와 움직이는 방법 | 구도·부품을 바꿀 때만 |

`plan.py`의 풀이

| 이름 | 뜻 |
|---|---|
| `ACCENT_HEX`, `ACCENT`, `BG_NAVY`, `CREAM` | 강조색, 무대색, 마스코트 머리색 |
| `BEAT_CAM` | 구간 → 카메라(`wide` 전신 + 카드, `card` 카드 중심, `face` 얼굴 가까이) |
| `MASCOT_BEAT` | 구간 → 표정(`expr`)과 동작(`action`) |
| `OVERLAYS` | 구간마다 얹을 제목 띠 PNG와 시각 |
| `SUB_TOP` | 자막 윗줄 높이(픽셀) |

`script.json`에서 이 팩이 읽는 것

- `title` → 첫 구간의 제목 띠, 결과 카드의 머리글.
- 구간의 `keyword` → 키워드 칩과 둘째 구간부터의 제목 띠.
- 구간 id `hook`의 `chat[0]` → 메시지 카드(그 초에 뜬다).
- 구간 id `ask`의 `chat` → 단톡 카드. 대화 시각마다 한 줄씩 는다.
- 구간 id `wait`의 `clock`(from → to)과 `gauge`(label, from → to) → 시계 바늘과 눈금 막대.
- 구간 id `decide`의 `chat[0]` → 알림 카드. 그 초에 떨어지고 마스코트가 움찔한다.
- `result`, `stamp` → 결과 카드, 그 초에 찍히는 도장과 색종이.

구간 id(`hook`, `ask`, `wait`, `decide`, `punch`)가 다른 대본이면 `plan.py`의 `BEAT_CAM`·`MASCOT_BEAT`와 `create_scene.py`의 '카드' 블록(`if "hook" in BEAT:` …)을 구간에 맞게 고친다. 카드 그림은 `cards.py`, 마스코트 생김새와 동작은 `create_scene.py`의 '마스코트' 블록과 `act()`에 있다.

고치는 순서

1. 음성 길이를 잰다: `ffprobe -v error -show_entries format=duration -of csv=p=0 <음성>`. `seconds` = 올림(초), `frames` = 초 × 24.
2. 구간(`beats`)을 나누고 구간마다 `start`·`end`(초), 내레이션, 키워드, 화면에 보일 것(`chat`, `clock`, `gauge`, `stamp`, `result`)을 쓴다.
3. 자막 타이밍이 없으면 음성의 쉬는 곳을 찾는다: `ffmpeg -hide_banner -i <음성> -af silencedetect=noise=-35dB:d=0.25 -f null -`. `silence_end`에서 다음 `silence_start`까지가 말하는 구간이다. 문장을 그 구간에 배정해 `subs`를 쓴다. 한 줄은 12자 안팎, 줄바꿈은 `\\N`.
4. `python scripts/plan.py`를 돌려 읽힌 값을 찍어 본다.
5. 1~3단계를 돌려 시트를 보고 `plan.py`와 `create_scene.py`를 고친다.

프레임 세는 법: `plan.py`는 0부터 센다. 블렌더는 1부터라서 스크립트가 알아서 1을 더한다.

한계
- 마스코트는 한 명이다. 둘 이상이면 '마스코트' 블록을 함수로 묶어 두 번 만들어야 한다.
- 카드 종류는 예제의 여섯 가지다. 새 종류는 `cards.py`에 그림을, `create_scene.py`에 띄우는 줄을 더한다.

## 6. 중간 검수

1. 1단계 뒤: `tex/`의 그림을 직접 열어 본다(`sheet.py`로 한 장에 붙여도 된다).
2. 3단계 시트를 직접 열어 본다. 볼 것:
   - 마스코트 얼굴(눈·입)이 구간에 맞는 표정인가.
   - 카드가 화면 밖으로 나가거나 제목 띠·자막과 겹치지 않는가(카드는 화면 위 17~47%, 자막은 73% 아래).
   - 카드 글자가 읽히는가, 글자가 카드 밖으로 넘치지 않는가.
   - 눈금 막대와 시계 바늘이 카드 위 제자리에 있는가.
   - 무대가 뿌옇게 뜨지 않았는가.
3. 고칠 것이 있으면 스크립트를 고치고 1~3단계를 다시 한다. `tests/`의 옛 스틸은 지우고 다시 뽑는다(있는 파일은 건너뛰기 때문이다).
4. 5단계 뒤: `ffmpeg -ss <초> -i out.mp4 -frames:v 1 check.png`로 두세 장을 뽑아 화면 위 그림과 자막의 글자·위치를 본다.

## 7. 함정

이 팩을 만들면서 실제로 겪은 것만 적는다.

- **세로 화면은 가로 화각이 좁다.** 렌즈 50mm에서 가로 약 23도다. 카메라를 가까이 두면 피사체가 잘린다. 보이는 폭은 거리 × 0.4쯤이다.
- **`transform_apply(scale=True)`는 자리까지 굳힌다.** 기본값이 location=True라서 원점이 0으로 가고, 그 뒤에 넣은 위치 키프레임이 두 배로 먹는다. `location=False, rotation=False, scale=True`로 쓴다.
- **부모를 건 자식의 자리는 부모 기준이다.** 세계 좌표로 만든 뒤 부모만 걸면 엉뚱한 곳에 간다.
- **밝은 재질 + 센 조명은 하얗게 날아간다.** 색 관리는 Standard다. 흰색은 0.8~0.86, 조명은 스틸을 보며 낮춘다.
- **반투명 발광면은 화면을 뿌옇게 만든다.** 빛줄기 원뿔은 알파 0.02, 발광 0.35로 낮춰야 했다.
- **블렌더 안의 파이썬에는 Pillow가 없다.** 그림은 `cards.py`(일반 파이썬)에서 만든다.
- **블렌더는 스크립트가 예외로 멈춰도 종료 코드 0으로 끝난다.** 명령에 `--python-exit-code 1`을 붙여야 실패가 종료 코드 1로 나온다.
- **이어 렌더.** 있는 프레임은 건너뛴다. 장면을 고친 뒤에는 `frames/`와 `tests/`의 옛 파일을 지워야 새로 렌더된다.

## 8. 실측 시간

시험 환경: RTX 3070 Ti 8GB, 드라이버 560, Windows 10, 블렌더 5.2.3, 공통 예제 대본(15초, 360프레임).

| 단계 | 시간 |
|---|---|
| `cards.py`, `create_scene.py` | 각각 몇 초 |
| 검수 스틸 540×960, EEVEE 16샘플 | 장당 1~2초 |
| 최종 렌더 1080×1920, EEVEE 16샘플, 360장 | 223초(장당 약 0.6초) |
| `finish.py`(360장 → 15초 MP4) | 10초 안쪽 |

## 9. 완료 기준

```
ffprobe -v error -show_entries stream=codec_type,codec_name,width,height,r_frame_rate,duration,sample_rate -of compact out.mp4
```

- 영상 1080×1920, 24fps, 길이 = `frames` ÷ 24초.
- 오디오 트랙이 있고(`--audio`를 줬으면 소리가 난다), 길이가 영상과 같다.
- 결과에서 뽑은 스틸을 눈으로 확인했다.
- 사용자에게 알린다: 결과 파일 경로, 걸린 시간, 남은 문제(시험하지 못한 것, 어색한 컷).

## 10. 라이선스

자세한 것은 `LICENSES.md`.
- 블렌더로 만든 영상은 만든 사람 것이다. 상업 이용에 제한이 없다.
- 외부 3D 소재·그림·음원을 쓰지 않는다. 장면과 그림은 전부 코드로 만든다.
- 글꼴은 팩에 없고 PC의 글꼴을 쓴다. 게시용이면 Noto Sans KR(OFL)을 권한다.
- 음성은 팩에 없다. 넣는 파일의 권리는 사용자가 확인한다.
- `bpy`를 쓰는 스크립트를 밖으로 배포하려면 GPL 호환 조건이어야 한다는 것이 블렌더 재단의 안내다.

## 11. 쓰지 않는 것

영상 생성 AI, 이미지 생성 AI, 유료 API, 내려받는 3D 소재를 쓰지 않는다. 효과음도 ffmpeg `aevalsrc`로 합성한다.
