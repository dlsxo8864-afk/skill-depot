# 리모션 관절 종이인형 썰 영상 (llmvid-remotion-paper-puppet)

검증된 예제와 절차를 묶은 팩이다. 버튼 하나로 끝나는 자동 도구가 아니다. `example/`의 코드를 새 대본에 맞게 고쳐 쓰고, 스틸을 눈으로 보며 다듬는다.

```
llmvid-remotion-paper-puppet/
  SKILL.md        이 문서
  LICENSES.md     라이선스
  example/
    package.json          remotion 4.0.542, react 19.3.1, typescript 5.9.3 (engines.node: ^20.19.0 || ^22.13.0 || >=24)
    remotion.config.ts
    tsconfig.json
    public/README.txt     음성·글꼴을 어디에 두는지
    src/index.ts
    src/Root.tsx          컴포지션 2개 등록 (PaperOffice, PaperPreview)
    src/StoryFilm.tsx     장면 + 자막 + 소리를 겹친다
    src/script.json       대본(모든 팩이 같은 형식)
    src/script.ts         대본을 읽어 값으로 내놓는다
    src/StoryData.ts      대본에서 장면 구간·자막을 만든다
    src/common.tsx        NARRATION·MUSIC 경로, 자막 상자
    src/fonts.ts          자막 글꼴 찾기
    src/PaperScene.tsx    [풀이] 구간마다의 배치와 동작
    src/PaperAssets.tsx   인물·책상·프린터·종이 부품
```

## 1. 이 스킬이 만드는 것

대본을 **관절 종이인형풍 세로 영상**(1080×1920, 24fps, MP4)으로 만든다. 그림 파일을 쓰지 않고 Remotion(React) 코드 안의 SVG 도형으로 오려 붙인 종이 질감과 그림자 효과, 관절이 꺾이는 인형 3명, 책상, 말풍선, 벽시계, 눈금 띠, 결과 간판(냄비 그림과 도장), 자막을 직접 그린다.

예제(`example/`)는 공통 예제 대본 「점심 메뉴 정하는 법」 15초(360프레임), 장면 5개다. 같은 묶음의 다른 팩도 모두 이 대본을 쓰고, 팩마다 화풍과 연출만 다르다.
대화는 인물 머리 위 **말풍선**으로 대본의 시각에 뜬다.

**잘 맞는 대본**
- 1인칭 썰, 사무실 이야기, 등장인물 3명(주인공 woman, 동료 new, 팀장 lead) 안팎의 이야기.
- 15~30초 안팎, 구간 4~7개. 대화가 짧은 것(한 줄 8자 안팎).

**안 맞는 대본(한계)**
- **구간 구성이 다른 대본은 장면 블록을 새로 짜야 한다.** 장면 파일(`src/PaperScene.tsx`)의 블록은 구간 id(hook, ask, wait, decide, punch)마다 무엇을 보여 줄지를 정해 둔 것이다. 대사와 시각은 `script.json` 만 바꾸면 따라오지만, 인물의 자리와 동작은 블록에 있다.
- **사람 얼굴 연기나 입 모양 맞춤(립싱크)은 없다.** 인물의 감정과 행동은 눈길(`look`), 눈썹(`brow`), 자세(`pose`), 손 위치(`handTarget`)로만 표현한다.
- 배경은 사무실 한 가지다. 다른 장소나 소품은 부품 파일에 새로 그려야 한다.
- 실사, 제품 실물, 장소가 끊임없이 바뀌는 이야기에는 맞지 않는다.

## 2. 입력

사용자에게 받을 것:

| 입력 항목 | 설명 | 비고 |
|---|---|---|
| 대본 | 15~30초 안팎, 말하는 순서대로 정리된 글 | `src/script.json` 형식으로 옮긴다 |
| 음성 파일 | `public/audio/narration.wav` 또는 mp3 경로에 둘 음성 | 없어도 됨. 없으면 소리 없는 영상으로 렌더된다 |
| 배경음 파일 | `public/audio/` 아래에 둘 배경음 파일 | 선택 사항. 기본값은 `null`(무음)이다 |
| 자막 타이밍 | 문장마다 시작·끝 프레임(또는 시작·끝 초) | 없으면 음성 파일에서 쉬는 구간을 찾아 프레임으로 계산한다 |
| 저장 폴더 | 렌더 결과물(MP4)과 스틸(PNG)을 저장할 경로 | 기본은 프로젝트 안 `out/` 폴더를 쓴다 |

음성도 타이밍도 없으면 문장 길이에 비례해 어림으로 프레임을 나누고, 어림값으로 작업했음을 사용자에게 알린다.

## 3. 먼저 확인할 환경

| 필요한 것 | 확인 명령 | 비고 |
|---|---|---|
| Node.js | `node -v` | `package.json` 조건은 `^20.19.0 \|\| ^22.13.0 \|\| >=24`. 시험 환경은 v22.14.0 |
| npm | `npm -v` | 패키지 설치(`npm install`)에 쓴다 |
| ffmpeg · ffprobe | `ffmpeg -version` | 음성 구간 감지, 결과 영상 규격 확인에 쓴다 |

- 위 도구 중 없는 것이 있으면 **임의로 설치하지 말고 사용자에게 먼저 묻는다.**
- `npm install`은 외부 패키지를 내려받으므로 **사용자가 허락한 뒤** 처음 한 번만 실행한다. 새 폴더에서의 `npm install` 과정은 시험에서 확인하지 못했다(시험은 같은 버전의 기존 node_modules를 연결하여 진행했다).
- Remotion은 렌더할 때 Chrome Headless Shell을 사용한다. 로컬에 설치되어 있지 않으면 첫 렌더 시 내려받으려 하므로, 이 또한 사용자에게 미리 알리고 허락을 받는다.
- 운영체제 시험은 Windows 10에서만 진행했다. macOS와 리눅스 환경에서의 동작은 확인하지 못했다.

## 4. 절차

모든 명령은 `example/`을 복사한 작업 폴더 안에서 실행한다. 경로는 그 폴더 기준 상대 경로다.

1. **예제를 작업 폴더로 복사한다.**
   팩의 `example/` 폴더를 사용자가 지정한 작업 폴더로 통째로 복사한다. 팩 원본 파일은 수정하지 않는다.
2. **패키지를 받는다(사용자 허락 뒤).**
   ```
   npm install
   ```
3. **타입 검사를 수행한다.**
   ```
   npx tsc --noEmit
   ```
4. **스틸 한 장으로 동작을 확인한다.**
   코드를 고치기 전에 기본 예제가 정상 작동하는지 프레임 30번 스틸을 뽑아 확인한다.
   ```
   npx remotion still src/index.ts PaperOffice out/f0030.png --frame=30
   ```
5. **음성 구간으로 타이밍을 정한다.**
   제공된 음성 파일이 있으면 ffmpeg로 묵음 구간을 탐지하여 발화 시작과 끝 구간을 잡는다.
   ```
   ffmpeg -i narration.wav -af silencedetect=noise=-35dB:d=0.25 -f null -
   ```
   출력되는 `silence_start`와 `silence_end`를 기반으로 구간과 자막의 시작·끝 초를 정한다.
6. **`script.json`과 `common.tsx`를 고친다.**
   - 음성 파일을 쓸 경우 `public/audio/narration.wav` 위치에 복사하고, `src/common.tsx`의 `NARRATION`을 `'audio/narration.wav'`로 변경한다(배경음이 있다면 `MUSIC`도 설정).
   - `src/script.json`에 길이(`seconds`, `frames`), 구간(`beats`), 대화(`chat`), 자막(`subs`)을 쓴다. `StoryData.ts`는 이 파일에서 장면 구간과 자막을 만든다(고치지 않는다).
7. **장면 블록을 고친다.**
   구간 구성이 예제와 다르면 `src/PaperScene.tsx`의 구간 블록(`{id === 'hook' && <>…</>}`)을 새 대본 연출에 맞게 고친다. 필요한 소품이나 인물 외형 변경이 있다면 부품 파일을 수정한다.
8. **스틸 검수를 진행한다.**
   수정 후 다시 `npx tsc --noEmit`을 거쳐, 각 장면의 대표 프레임을 스틸로 뽑아 눈으로 확인한다(6절 참고).
   빠른 모션 확인이 필요할 경우 6초 미리보기 렌더를 활용한다.
   ```
   npx remotion render src/index.ts PaperPreview out/preview.mp4
   ```
9. **앞 3초를 렌더하여 소리와 싱크를 확인한다.**
   음성을 넣었다면 72프레임(3초)을 먼저 렌더하여 오디오 스트림과 영상 타이밍을 검증한다.
   ```
   npx remotion render src/index.ts PaperOffice out/head.mp4 --frames=0-71
   ```
10. **최종 렌더를 수행한다.**
    ```
    npx remotion render src/index.ts PaperOffice out/final.mp4
    ```
11. **ffprobe로 결과를 검증한다.**
    결과 파일의 해상도, 프레임 수, 재생 시간, 오디오 스트림 유무를 확인한다(9절 참고).

## 5. 대본에 맞춰 고칠 곳

대본과 연출을 나눠 두었다. 장면 파일 안에는 대사도 프레임 번호도 없다.

| 파일 | 담긴 것 | 새 대본에서 |
|---|---|---|
| `src/script.json` | 대본. 길이(`seconds`, `frames`), 등장인물(`cast`), 구간(`beats`)마다 시작·끝 초, 대화(`chat`: 초, 누구, 문구), 시계(`clock`), 눈금(`gauge`), 도장(`stamp`), 결과(`result`), 자막(`subs`) | 새로 쓴다 |
| `src/script.ts`, `src/StoryData.ts` | 대본을 읽어 장면 구간(`STORY_SCENES`)과 자막(`STORY_CAPTIONS`)을 만든다 | 고치지 않는다 |
| `src/PaperScene.tsx` | [풀이] 구간 id 마다의 블록. 인물 자리·자세·시선, 소품 | 구간 구성이 달라지면 고친다 |
| `src/common.tsx` | `NARRATION`, `MUSIC` 경로 | 소리를 넣을 때 |

예제의 구간 블록

| 구간 id | 보여 주는 것 |
|---|---|
| `hook` | 주인공이 자리에서 묻는다. 내 대화가 말풍선으로 뜬다 |
| `ask` | 세 사람이 한 화면에. 동료와 팀장의 대답이 차례로 말풍선으로 뜬다 |
| `wait` | 주인공 가까이. 벽시계가 돌고 눈금 띠가 찬다. 화면이 노을빛으로 바뀐다 |
| `decide` | 팀장이 걸어 들어와 한마디 한다(말풍선) |
| `punch` | 결과 간판이 내려오고 도장이 찍힌다. 두 사람이 말풍선으로 답한다 |

- 등장인물 순서가 인형 종류를 정한다: `cast` 의 첫째가 주인공(`woman`), 둘째가 동료(`new`), 마지막이 팀장(`lead`).
- 블록 안에서 `p` 는 그 장면의 진행도(0~1), `lf` 는 장면 안에서 지난 프레임이다. 대본의 초를 장면 안 프레임으로 바꿀 때는 `fr(초) - 장면 시작 프레임` 을 쓴다.
- 블록이 없는 구간 id 는 배경만 나온다. 구간 id 를 바꾸면 블록의 `id === '…'` 과 `beat('…')` 호출을 같이 고친다.
- 결과 그림(냄비)은 `Sign` 안의 SVG 다. 결과물이 다르면 그 그림을 새로 그린다.
- 미리보기 컴포지션(`PaperPreview`)은 첫 구간·셋째 구간·마지막 구간을 2초씩 보여 준다.

고치는 순서

1. 음성 길이를 재서 `seconds`(올림)와 `frames`(초 × 24)를 정한다.
2. 구간(`beats`)을 나누고 구간마다 `start`·`end`(초), 대화, 화면에 보일 것을 쓴다.
3. 자막(`subs`)을 음성에 맞춘다. 한 줄 12자 이하, 줄바꿈은 `\\N`, 두 줄까지.
4. `npx tsc --noEmit` 으로 타입을 검사하고 스틸로 본다(6절).

### 종이 부품 주요 인자

- `PaperPerson`:
  - `kind`: `'woman'`(주인공), `'new'`(신입), `'lead'`(팀장)
  - `pose`: `'stand'`, `'walk'`, `'seat'`
  - `look`: 숫자. 음수면 왼쪽, 양수면 오른쪽, 0이면 정면(기본 0)
  - `brow`: true/false. 눈썹 표정을 켜고 고개를 조금 기울인다
  - `typing`: true/false. 타이핑 동작
  - `reach`: 숫자 0~1. 팔을 뻗는 정도
  - `carry`: true/false. true면 손에 종이를 든다
  - `handTarget`: `{x, y}`(인물 기준 좌표). 주면 손이 그 좌표로 간다
  - `tick`: 스텝 틱(정수). 동작이 이 값에 따라 한 칸씩 바뀐다
  - `s`: 배율 (기본 1)
- 손 좌표 함수: `paperHand(reach)`는 팔을 뻗은 정도에 따른 손 좌표(인물 기준)를 돌려준다. 부품이 아니라 함수다
- 배경 및 소품: `PaperRoom`(인자 없음. `card` 그림자 필터를 여기서 정의한다), `PaperDesk({s, monitor})`, `PaperPrinter({paper, emerge})`, `PaperSheet({scale, flat, rotate})`
  - `emerge`: 숫자 0~1. 프린터에서 종이가 나온 정도

- 이 예제에서 장면 파일 안에 더한 부품: `Bubble`(오려 붙인 말풍선: `text`, `show` 나타난 뒤 지난 프레임, `side` 꼬리 방향, `color`), `Clock`(`minutes` 12시간 기준 분), `Gauge`(`val` 0~1, `label`), `Sign`(결과 간판: `stamp` 도장이 찍힌 뒤 지난 프레임).

## 6. 중간 검수

렌더 완료 후 확인하지 않고, 작업 중간마다 스틸을 뽑아 눈으로 직접 검수한다.

```
npx remotion still src/index.ts PaperOffice out/check_scene.png --frame=<확인프레임>
```

구간마다 최소 한 장 이상의 스틸을 뽑아 검수한다. 예제에서 쓸 만한 프레임: 30(hook), 66(hook, 대사가 뜬 뒤), 110·136(ask), 180·210(wait), 236·270(decide), 300·340(punch, 도장 앞뒤).

검수 체크리스트:
- **자막 위치와 줄바꿈**: 자막(하단 safe zone 기준 bottom 290px, 64px 굵은 글씨)이 화면 좌우 경계를 벗어나지 않는지, 2줄 이상일 때 `\n` 줄바꿈이 자연스러운지 확인한다.
- **인물 및 소품 배치**: 종이 인형과 책상, 대사 표시(말풍선·대사창), 결과 그림이 서로 엉뚱하게 겹치거나 가려지지 않는지 확인한다.
- **종이 질감 및 그림자**: 부품마다 종이 그림자 필터가 의도대로 적용되어 깊이감이 살아있는지 확인한다.

## 7. 함정

- **부품마다 종이 그림자 필터(`url(#card)`)를 적용해야 한다.**
  종이 인형의 핵심 연출은 두꺼운 종이를 오려 겹쳐 놓은 듯한 음영이다. `card` 필터는 `PaperRoom`이 `<defs>`에 정의한다. `PaperRoom`을 그리지 않으면 필터가 없어 그림자가 사라진다. 새 부품에도 `filter="url(#card)"`를 건다.
- **12fps 스텝 애니메이션 계산식을 지킨다.**
  종이인형 팩은 부드러운 24fps 연속 애니메이션 대신 스톱모션 종이 애니메이션 느낌을 내기 위해 `tick = Math.floor(frame / 2)`를 사용한다. 이는 2프레임마다 1틱씩 움직이는 12fps 스텝 연출이다. 모션 로직을 작성할 때 프레임을 직접 쓰지 않고 `tick`을 기준으로 계산해야 종이 인형 특유의 끊어지는 수제 느낌이 유지된다.
- **SVG viewBox는 원본 해상도(1080×1920) 기준이다.**
  픽셀 팩과 달리 종이인형 팩은 viewBox 자체가 1080×1920으로 전체 캔버스를 그대로 쓴다. 좌표 계산 시 화면 크기를 그대로 기준으로 잡는다.
- **`CaptionKR-Bold.ttf` 404 로그는 정상이다.**
  렌더 로그에 `fonts/CaptionKR-Bold.ttf` 404가 찍힌다. 팩에 글꼴 파일이 없어 시스템 글꼴로 넘어가는 것이고 렌더는 멈추지 않는다.
- **시스템 한글 글꼴 로드 확인.**
  글꼴을 찾지 못하면 기본 시스템 글꼴로 렌더된다. Windows 환경에서는 시스템 글꼴 Noto Sans KR로 정상 렌더되는 것을 확인했다. macOS와 리눅스 글꼴 후보는 확인하지 못했다.
- **구간 id 와 코드의 결합.**
  장면 블록은 `{id === 'hook' && ...}` 처럼 대본의 구간 id 에 묶여 있다. 블록이 없는 id 의 구간은 배경만 나온다.

## 8. 실측 시간

측정 환경: Windows 10, RTX 3070 Ti 8GB, Node 22.14.0, Remotion 4.0.540(기존 node_modules 연결). 타입 검사·스틸·미리보기 값은 2026-11-10 이전 예제에서, 전체 렌더는 2026-11-15 공통 대본에서 잰 값이다.

| 작업 | 명령 / 대상 | 소요 시간 / 결과 크기 |
|---|---|---|
| 타입 검사 | `npx tsc --noEmit` | 2.3초 |
| 스틸 첫 장 | `npx remotion still ... --frame=30` | 4.6초 |
| 미리보기 렌더 | `PaperPreview` 144프레임 (6초) | 8.4초 |
| 전체 최종 렌더 | `PaperOffice` 소리 없이 360프레임 (15초) | 19초 |

- 최종 렌더 출력 스펙: H.264 영상(1080×1920, 24fps, 360프레임), 15.000초. 소리를 넣지 않으면 오디오 스트림은 없다.
- 음성과 글꼴 파일이 프로젝트에 없는 상태에서도 스틸과 미리보기 렌더가 성공적으로 완료되었다.

## 9. 완료 기준

1. `npx tsc --noEmit`이 타입 에러 없이 반환 코드 0으로 통과한다.
2. 구간마다 스틸을 눈으로 검수하여 인물 위치, 종이 질감 및 그림자, 자막 배치가 올바른지 확인했다.
3. 최종 결과물(`out/final.mp4`)을 ffprobe로 검증하여 규격이 일치하는지 확인한다.
   ```
   ffprobe -v error -show_entries format=duration:stream=codec_type,width,height,nb_frames -of json out/final.mp4
   ```
   - 영상 스트림: 폭 1080, 높이 1920, 프레임 수 = 대본의 `frames`(예제 360, 15초).
   - 오디오 스트림: 음성을 넣은 경우 aac 오디오 트랙이 정상 존재하고 무음이 아님을 확인한다.
4. 사용자에게 결과 파일 경로, 최종 소요 시간, 확인하지 못한 사항(대본 수정에 따른 연출 변경점, 시스템 글꼴 로드 상태 등)을 명확히 보고한다.

## 10. 라이선스 (자세한 내용은 `LICENSES.md`)

- **Remotion**: 개인, 비영리 단체, 직원 3명 이하의 영리 회사는 무료로 사용 가능하다. **직원 4명 이상인 영리 기업은 유료 라이선스가 필요하다.** 사용자 환경이 기업인 경우 렌더 전에 고지한다.
- **예제 코드**: 이 프로젝트에서 LLM으로 작성했다. 따로 라이선스를 붙이지 않았다(`package.json`의 license: UNLICENSED).
- **글꼴·음성**: 번들 파일이 제공되지 않으며 사용자가 준비하거나 시스템에 설치된 폰트를 사용한다. 상업적 사용 시 권리를 확인한다.
