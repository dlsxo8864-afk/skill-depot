# 블렌더 복셀 '만약에' 쇼츠 (llmvid-blender-voxel-whatif)

검증된 예제와 절차를 묶은 팩이다. 버튼 하나로 끝나는 자동 도구가 아니다.
`example/`의 스크립트로 공통 예제 대본 「점심 메뉴 정하는 법」(15초, 360프레임)을 실제로 만들었다. 같은 묶음의 다른 팩도 모두 이 대본을 쓰고, 팩마다 화풍과 연출만 다르다. 새 대본은 **타임라인 JSON 한 파일**(샷·인물·동작·제목·자막)을 새로 써서 만든다. 세트 3종과 동작 9종 안에서는 파이썬을 고치지 않고 장면 수·장소·카메라·동작을 바꿀 수 있다.

형식은 인스타그램의 복셀 '만약에' 연작(블록 인물, 타일 색을 섞은 세트, 큰 군중, 과감한 카메라, 굵은 흰 자막)을 보고 정했다. 그 계정의 캐릭터·제목·대본은 쓰지 않았고, 예제의 대본과 인물은 새로 만들었다.

세트·인물·군중은 전부 코드로 만든 상자다. 외부 3D 모델·텍스처·HDRI·이미지가 필요 없고, 영상·이미지 생성 AI 없이 블렌더와 ffmpeg만으로 끝까지 만든다.

```
llmvid-blender-voxel-whatif/
  SKILL.md
  LICENSES.md
  example/
    create_voxel.py         타임라인을 읽어 세트·인물·군중·카메라·동작을 만들고 .blend 로 저장한다(시작점)
    timeline.example.json   [대본] 예제 타임라인. 샷 5개, 인물 3명(표정만 다른 사본 2개 포함 5개 정의), 제목 카드, 자막 5줄
    preview_checks.py       저장한 .blend 에서 샷마다 스틸을 1장 또는 3장 뽑는다
    render_final.py         전체 프레임을 PNG 로 뽑는다(끊겨도 다시 실행하면 이어서)
    finish.py               프레임 + 음성 + 제목 카드·자막을 MP4 로 합친다
    fontfind.py             자막용 한글 글꼴을 찾는다
    sheet.py                그림 여러 장을 한 장 시트로 붙인다(검수용)
```

## 1. 이 스킬이 만드는 것

- 정육면체를 쌓은 블록 인물(키 약 1.9 m, 머리 0.5 m 상자). 얼굴은 8×8 픽셀 그림이고 머리 모양·옷 색·안경·헤드셋을 고른다.
- 세트 3종: 공원(park), 방(room), 경기장(stadium: 무대·LED 전광판·관중 수천 명). 바닥과 벽은 픽셀 질감(가장 가까운 픽셀로 확대)이라 가까이 찍어도 블록 느낌이 남는다.
- 샷마다 카메라 한 대. 시작·끝 위치와 바라볼 점을 주면 샷 안에서 부드럽게 움직이고, 샷이 바뀌면 바로 넘어간다(컷).
- 동작 9종: idle, walk, sit, nod, shake, wave, cheer, turn_head, point.
- 결과: 1080×1920 세로, 24fps MP4. 예제는 15초(360프레임).

가장 중요한 한계
- **표정 연기와 립싱크가 없다.** 얼굴은 인물마다 4종(smile, neutral, surprised, sleepy) 중 하나로 고정된다. 샷마다 표정을 바꾸려면 같은 옷의 인물을 face만 다르게 두 번 정의한다(예: `noeul`, `noeul_surprised`).
- **물건을 들거나 건네지 못한다.** 손가락과 잡기가 없고, 들고 다니는 소품도 없다.
- **동작은 정해진 9종을 시간에 맞춰 붙이는 것뿐이다.** 새 동작은 `create_voxel.py`에 함수를 짜서 `ACTIONS`에 넣어야 한다.
- **세트는 3종뿐이다.** 지하철·주방 같은 장소는 `SETS`에 세트 함수를 새로 짜야 한다.
- 화면 글자(제목·자막)는 렌더 뒤 ffmpeg로 얹는다. 세트 안 간판 글씨는 없다.

잘 맞는 대본
- "만약 ~라면" 식 상상 시나리오. 내레이션이 끌고 가는 10~60초 쇼츠.
- 장소가 2~4번 바뀌고, 공연장·군중 같은 큰 그림이 한 번쯤 나오는 이야기.
- 반응을 몸짓(고개 끄덕임·젓기, 환호, 가리키기, 손 흔들기)으로 크게 보여 주면 되는 이야기.

안 맞는 대본
- **대사를 주고받는 연기, 립싱크, 미묘한 표정 변화가 웃음이나 감정의 핵심인 이야기.**
- **물건을 집고 건네는 행동이 많은 이야기.**
- 실사 느낌이 필요한 이야기. 이 팩은 블록 화풍이다(사람 모양이 필요하면 같은 v1.2의 `llmvid-blender-psa-parody`가 가깝다).

## 2. 입력

| 입력 | 필수 | 설명 |
|---|---|---|
| 대본 | 필수 | 내레이션 문장과 장면 나눔 |
| 타임라인 파일 | 필수 | 샷·인물·동작·제목·자막을 담은 JSON(`example/timeline.example.json` 본뜸, 형식은 5절) |
| 음성 파일 | 선택 | wav/mp3. 없으면 소리 없는 영상(조용한 오디오 트랙)이 된다 |
| 배경음 파일 | 선택 | wav/mp3. 음량 0.3으로 섞인다 |
| 저장 폴더 | 필수 | 작업 폴더. 예제 360프레임 PNG가 약 634MB다 |

## 3. 먼저 확인할 환경

```bash
blender --version      # Blender 5.2.3 LTS 에서 전 과정을 확인했다. 4.5 LTS 는 확인하지 못했다(코드에는 4.x 경로도 넣어 두었다). PATH 에 없으면 실행 파일 위치를 사용자에게 묻는다
ffmpeg -version        # libx264, libass(자막 필터)가 든 빌드
python --version       # 3.10 이상
python -c "import PIL; print(PIL.__version__)"   # Pillow (sheet.py 검수 시트에만 쓴다)
```

- 없는 도구가 있으면 사용자에게 알리고 설치 여부를 묻는다. 프로그램 설치나 내려받기는 사용자 허가를 받은 뒤에만 한다.
- 한글 글꼴: `python scripts/fontfind.py`로 확인한다. Noto Sans KR → 맑은 고딕 순으로 찾는다. 못 찾으면 사용자에게 글꼴 파일(.ttf/.otf)을 받아 `finish.py --font`로 넘긴다.
- 제목 카드도 같은 글꼴로 나간다. 픽셀 글꼴로 제목을 쓰려면 권리가 분명한 픽셀 글꼴 파일을 사용자에게 받아 `--font`로 넘긴다(제목과 자막이 같은 글꼴이 된다).
- EEVEE는 그래픽 카드를 쓴다. 시험 환경은 Windows 10 + RTX 3070 Ti 8GB다. 그래픽 카드가 없는 PC는 확인하지 못했다.
- 외부 3D 모델·텍스처·HDRI를 쓰지 않으므로 에셋 내려받기는 필요 없다.

## 4. 절차

작업 폴더를 따로 만들고 그 안에서 명령을 돌린다. 팩의 `example/`은 원본으로 두고 작업 폴더의 `scripts/`로 복사해 쓴다. 새 대본의 타임라인은 작업 폴더에 `timeline.json`으로 새로 쓴다.

```
작업 폴더/
  scripts/                 example 사본
  timeline.json            새 대본의 타임라인(scripts/timeline.example.json 을 본떠 쓴다)
  scene.blend              1단계 결과
  previews/                2단계 결과 proof_<순번>_<샷 id>_<프레임>.png
  proofs.png               3단계 검수 시트
  frames/                  4단계 결과 frame_0001.png ~ , _signature.txt
  render-manifest.json     4단계 결과(.blend 옆에 생긴다)
  subs.ass, fonts/         5단계 finish.py 가 만든다
  out.mp4                  최종 영상
```

경로 규칙. 셋이 서로 달라서 헷갈린다.
- `create_voxel.py`에 넘기는 상대 경로는 **스크립트 폴더(`scripts/`) 기준**으로 풀린다. 그래서 타임라인과 .blend는 **절대 경로**로 넘긴다.
- `preview_checks.py`, `render_final.py`의 출력 폴더 상대 경로는 **열린 .blend가 있는 폴더 기준**이다.
- `finish.py`는 **지금 있는 폴더**에 `subs.ass`와 `fonts/`를 만든다. 작업 폴더에서 실행한다.

### 0단계. 대본을 샷 표로 나눈다

예제의 샷 5개는 다음과 같다.

| 순번 | 샷 id | 시작(초) | 끝(초) | 세트 | 장면 | 자막 |
|---|---|---|---|---|---|---|
| 1 | hook | 0.0 | 3.0 | room(낮) | 나와 민수가 마주 앉아 있다. 내가 손을 흔들어 묻는다(wave). 0~1.6초 제목 카드 | 점심 메뉴, / 오늘도 못 정했죠? |
| 2 | ask | 3.0 | 6.0 | hook 세트 재사용 | 민수와 팀장이 차례로 고개를 젓는다(shake) | 물어보면 다들 / "아무거나요." |
| 3 | wait | 6.0 | 9.0 | park(가을, 저녁) | 내가 벤치에 앉아 꾸벅이고(졸린 얼굴), 민수가 길을 지나간다 | 시계는 가고, / 배는 고파 오고. |
| 4 | decide | 9.0 | 12.0 | stadium(밤, 관중 4000) | 경기장 전경 부감. 무대 위 팀장이 가리킨다 | 결국 팀장님이 / 정합니다. |
| 5 | punch | 12.0 | 15.0 | decide 세트 재사용(저녁, 조명 2.0) | 무대 정면. 둘이 끄덕이고 팀장이 환호한다(cheer) | 오늘도 / 김치찌개입니다. |

- 한 샷은 2~4초가 알맞다(예제는 3초 안팎). 컷 간격이 쇼츠 호흡을 정한다.
- 같은 장소를 다른 각도로 다시 보여 줄 때는 `reuse_set`으로 세트를 함께 쓴다(세트를 또 짓지 않는다).
- 샷은 빈틈없이 이어 쓴다(앞 샷 end = 다음 샷 start). 마지막 샷의 end가 영상 길이다.
- 블렌더 프레임은 1부터 센다. 샷의 첫 프레임은 `round(start × 24) + 1`, 끝 프레임은 `round(end × 24)`다.

### 1단계. 장면 만들기

```bash
blender --background --python-exit-code 1 --python scripts/create_voxel.py -- "<작업 폴더 절대 경로>/timeline.json" "<작업 폴더 절대 경로>/scene.blend"
```

- 끝에 `SCENE_OK frames=<프레임 수> shots=<샷 수>`가 찍히고 .blend가 저장된다. 예제는 `SCENE_OK frames=360 shots=5`.
- 인자를 빼면 스크립트 옆 `timeline.example.json`을 읽어 스크립트 옆 `scene.blend`로 저장한다.
- 모르는 세트·시간대·동작·얼굴·머리 모양·extras·계절·arm 값이나 cast에 없는 인물을 쓰면 `ValueError`로 멈추고 .blend를 저장하지 않는다(종료 코드 1).

### 2단계. 샷마다 스틸 뽑기

```bash
blender --background scene.blend --python-exit-code 1 --python scripts/preview_checks.py -- previews --each 3
```

- `--each 3`이면 샷마다 앞(첫 프레임+2)·가운데·끝(끝 프레임−2) 세 장, `--each 1`이면 가운데 한 장이다. 기본 크기 50%, 16샘플(`--percent`, `--samples`로 바꾼다).
- 결과는 `previews/proof_<순번>_<샷 id>_<프레임>.png`이고 끝에 `PREVIEW_OK stills=<장수> dir=<폴더>`가 찍힌다.

### 3단계. 검수 시트 만들기

```bash
python scripts/sheet.py proofs.png previews/proof_*.png --cols 3 --width 360
```

- 셸에서 `*`가 풀리지 않으면(일부 파워셸) 파일 이름을 나열한다.
- `proofs.png`를 직접 열어 6절 기준으로 본다.

### 4단계. 전체 프레임 렌더

검수가 끝나면 원본 크기(1080×1920), 32샘플로 전체를 뽑는다. 예제 15초에 몇 분 걸리므로 백그라운드로 돌린다.

```bash
blender --background scene.blend --python-exit-code 1 --python scripts/render_final.py -- frames --samples 32
```

- `frames/frame_0001.png`부터 저장한다. 24프레임마다 `FRAME_PROGRESS`, 끝나면 `RENDER_COMPLETE {...}` 한 줄과 .blend 옆 `render-manifest.json`이 생긴다.
- 끊겨도 같은 .blend로 다시 실행하면 온전한 프레임은 건너뛴다. .blend가 바뀌면 서명(`frames/_signature.txt`)이 달라져 같은 폴더에 처음부터 다시 뽑는다.

### 5단계. 합성 (영상 + 음성 + 제목 카드·자막)

```bash
python scripts/finish.py frames out.mp4 --timeline timeline.json --audio narration.wav
```

- **`--timeline`을 꼭 넘긴다.** 빼면 스크립트 옆 예제 타임라인의 제목·자막(「점심 메뉴 정하는 법」)이 들어간다.
- 제목 카드(`title`)는 화면 위쪽 큰 글자(112px, 검은 외곽선)로, 들어올 때 0.12초·나갈 때 0.22초 페이드한다. 자막(`captions`)은 흰 굵은 글자 66px + 검은 외곽선으로 화면 아래에서 430px 위에 놓인다(릴스 조작부를 피한 자리).
- 음성이 없으면 `--audio`를 뺀다(조용한 트랙이 들어간다). 선택: `--music 배경음`(음량 0.3), `--font 글꼴`, `--crf 20`.
- 작업 폴더에 `subs.ass`와 `fonts/`가 생긴다.

### 6단계. 최종 확인

9절 기준으로 `ffprobe`와 자막 스틸을 확인한다.

## 5. 타임라인 형식 — 대본에 맞춰 쓸 곳

새 대본에서는 이 파일만 새로 쓴다. 좌표는 세트 안 미터 단위 `[x, y, z]`이고 z가 위다. 블렌더 안에서는 세트마다 X로 400 m씩 떨어져 지어지지만, 타임라인에는 세트 안 좌표만 쓴다.

방향(`heading`, 도): 0이면 인물이 -Y를 본다(보통 카메라 쪽), 90이면 +X, 180이면 +Y, 270이면 -X. walk 중에는 걷는 방향으로 돈다.

맨 위

| 키 | 내용 | 예제 |
|---|---|---|
| `fps`, `width`, `height` | 프레임 속도, 크기 | 24, 1080, 1920 |
| `title` | `{text, start, end}` 제목 카드 | `"점심 메뉴\\N정하는 법"`, 0~1.6초 |
| `cast` | 인물 id → 외형 | me, me_sleepy, minsu, lead, lead_smile |
| `shots` | 샷 목록(시간 순) | 4개 |
| `captions` | `[{start, end, text}]` 자막 | 4줄 |

- 제목·자막 줄바꿈은 JSON 안에서 `\\N`으로 쓴다(ASS 줄바꿈).

cast (인물 외형)

| 키 | 값 | 기본값 |
|---|---|---|
| `skin`, `hair`, `top`, `bottom`, `shoes` | `"#RRGGBB"` | `#f1c9a2`, `#3a2a1f`, `#f2c12e`, `#34435e`, `#333333` |
| `hair_style` | `short`, `long`, `bald`, `cap`(윗옷 색 모자) | `short` |
| `face` | `smile`, `neutral`, `surprised`, `sleepy` | `smile` |
| `extras` | `["glasses"]`, `["headset"]`, 둘 다 | `[]` |

샷

| 키 | 내용 | 기본값 |
|---|---|---|
| `id` | 샷 이름. 마커·스틸 파일 이름에 쓰인다. 겹치면 안 된다 | 필수 |
| `start`, `end` | 초 | 필수 |
| `set` | `park`, `room`, `stadium` — 새 세트를 짓는다 | `set`과 `reuse_set` 중 하나 |
| `reuse_set` | 앞 샷 id. 그 샷의 세트를 그대로 쓴다 | |
| `set_options` | 세트별 옵션(아래 표) | `{}` |
| `time` | `day`, `evening`, `night` | `day` |
| `lamps` | 세트 조명 세기 배율 | 1.0 |
| `camera` | `from`, `to`, `look_from`, `look_to`, `lens` | from `[0,-10,3]`, to = from, look_from `[0,0,1]`, look_to = look_from, lens 35 |
| `actors` | `[{who, at, heading, actions}]` | `[]` |

- 카메라는 샷 안에서 `from`→`to`로 움직이며 `look_from`→`look_to`를 바라본다. 세로 화면이라 가로 화각이 좁다: lens 35에서 가로 약 32도(9 m 앞 화면 폭 약 5.2 m), 26에서 약 42도, 22에서 약 49도.
- 인물: `who`(cast id), `at`(기본 `[0,0,0]`, 무대 위는 z=1.5), `heading`(기본 0), `actions`.
- 동작: `{do, t0, t1, ...}`. t0·t1은 **샷 시작에서 센 초**다. t0 기본 0, t1 기본은 샷 길이.

동작

| do | 하는 일 | 추가 값 |
|---|---|---|
| `idle` | 숨 쉬듯 위아래 + 고개 살짝 좌우 | |
| `walk` | 지금 자리에서 `to`까지 일정한 속도로 걷는다(초당 1.8걸음). 걷는 방향으로 몸을 돌리고 끝난 뒤 그 방향을 유지한다 | `to: [x, y]` |
| `sit` | 의자 높이 0.5 m로 앉는다. t0가 0이면 샷 처음부터 앉아 있고, 0보다 크면 t0에서 0.25초 동안 앉는다. 일어나지 않는다 | |
| `nod` | 고개 끄덕임 반복 | |
| `shake` | 고개 젓기 반복 | |
| `wave` | 한 팔을 들어 흔든다. t0에서 4프레임 동안 들고, 끝나기 4프레임 전부터 내린다 | `arm`: `R`(기본) 또는 `L` |
| `cheer` | 두 팔을 들고 깡충 뛴다(팔은 wave와 같은 방식으로 들고 내림) | |
| `turn_head` | 고개를 angle도 돌려 유지한다(+는 위에서 볼 때 반시계 = 인물 기준 왼쪽) | `angle`(기본 30) |
| `point` | 한 팔을 앞으로 뻗어 유지한다 | `arm`: `R`(기본) 또는 `L` |

- `arm`: R은 인물이 카메라를 볼 때(heading 0) 화면 오른쪽 팔, L은 화면 왼쪽 팔이다.
- `turn_head`, `point`, `sit`은 t1 뒤에도 그 자세가 남는다. 되돌리려면 샷을 나눈다.
- 같은 관절을 쓰는 동작은 시간을 겹치지 않는다. 고개: idle·nod·shake·turn_head. 팔: walk·wave·cheer·point. 몸 높이: idle·sit·cheer. 겹치면 키가 섞여 자세가 튄다.
- walk 속도는 거리 ÷ (t1 − t0)다. 걸음 박자는 고정이라 초속 1.5 m(예제 값)를 넘기면 미끄러져 보일 수 있다(예제 값보다 빠르게는 시험하지 않았다).

세트

| 세트 | set_options | 안에 있는 것(세트 안 좌표) |
|---|---|---|
| `park` | `seed`(기본 42), `season`: spring·summer·autumn·winter(기본 autumn), `trees`(기본 16) | 60×60 m 잔디. x축을 따라 폭 2 m 모랫길(-1 < y < 1). 벤치 (1.5, 1.8) 좌판 높이 약 0.5 m(등받이가 +Y 쪽). 가로등 (-4, 2.2), (6, 2.2). 나무는 -2 ≤ y ≤ 2.5 이고 \|x\| ≤ 7 인 곳을 비워 둔다(인물 자리). 반지름 28 m 언덕 띠. 가을이면 낙엽 |
| `room` | `seed` | 바닥 x -4~4, y -5~3. 뒷벽 y=3, 좌우벽 x=±4, 높이 3.2 m, **천장 있음**(위에서 내려다보는 구도는 안 된다), 앞(-Y)은 열려 있다. 뒷벽 가운데 창(높이 2.0 m). 테이블 (0, 0.5) 상판 0.75 m, 의자 (-0.95, 0.5)와 (0.95, 0.5) 좌판 0.5 m. 스탠드 (3.2, 2.2) |
| `stadium` | `seed`, `crowd`(기본 3000) | 300×300 m 바닥. 무대 x -9~9, y 26~34, 윗면 높이 1.5 m(무대 위 인물은 `at`의 z를 1.5로). LED 전광판, 스피커 탑, 조명, 관중(한 메시), 응원봉, 먼 빌딩 |

- 예제처럼 마주 앉히려면 room의 두 의자 좌표에 heading 90(왼쪽 의자)과 270(오른쪽 의자)으로 둔다.
- `time`이 night면 하늘과 해가 어두워지고 세트 조명(가로등·스탠드·무대 조명)이 그림을 끌고 간다. `lamps`로 세기를 조절한다.

### 고치는 순서

1. 음성 길이를 잰다. `ffprobe -v error -show_entries format=duration -of csv=p=0 narration.wav`. 마지막 샷의 end를 이 길이 이상으로 잡는다.
2. 자막 구간을 잡는다. 시각이 따로 없으면 `ffmpeg -i narration.wav -af silencedetect=noise=-35dB:d=0.25 -f null -`의 `silence_end`~다음 `silence_start`가 말하는 구간이다. 문장을 이 구간에 나눠 `captions`에 넣고, 긴 문장은 `\\N`으로 두 줄로 나눈다.
3. 샷 표(0단계)대로 `shots`를 쓴다. 장소마다 `set`, 같은 장소 다른 각도는 `reuse_set`.
4. `cast`에 인물을 정의한다. 표정이 바뀌는 인물은 face만 다른 id를 하나 더 만든다.
5. 샷마다 카메라와 인물·동작을 넣는다. 1~3단계를 돌려 시트를 보고 좌표·lens를 고친다.
6. `title`을 넣고 4~5단계로 마무리한다.

## 6. 중간 검수

1. **3단계 시트에서 본다.**
   - 인물의 머리·손이 세로 화면 밖으로 잘리지 않았는지. 세로 화면은 가로가 좁아 양 끝 인물이 잘리기 쉽다.
   - 인물이 벽·가구·관중과 겹치지 않았는지, 발이 바닥(무대 위면 1.5 m)에 붙어 있는지.
   - 자세 동작(sit, turn_head, point)이 t0 전에 미리 나와 있지 않은지(앞 스틸).
   - 제목 카드 자리(위쪽 360px 아래)와 자막 자리(아래 430px 위)에 인물 얼굴이 오지 않는지.
2. 타임라인을 고쳤으면 1단계부터 다시 한다(1~3단계는 예제 기준 10초 안쪽).
3. **5단계 뒤** 자막이 나오는 시각으로 한 장 뽑아 글자 깨짐·줄바꿈·가림을 본다.
   ```bash
   ffmpeg -ss 4.5 -i out.mp4 -frames:v 1 check_sub.png
   ```

## 7. 함정

실제로 만들면서 겪은 것만 적는다.

- **옆모습 인물의 wave는 잘 안 보인다.** 예제의 방 장면에서 카메라 쪽 팔을 들었더니 팔이 얼굴을 가리고 그늘이 져 검은 덩어리로 보였고, 반대쪽 팔(`arm: L`)은 머리 뒤에 가렸다. 그래서 예제는 고개 젓기(shake)로 바꿨다. wave·cheer는 인물이 카메라 쪽을 볼 때(heading 0 근처) 쓴다.
- **자세 키가 하나뿐이면 샷 처음부터 그 자세가 된다.** 블렌더는 첫 키 앞을 첫 키 값으로 채운다. 처음 만든 코드에서 wave·cheer가 t0 전부터 팔을 들고 있었고, turn_head·point·sit도 같았다. 지금은 t0에 기본 자세 키를 먼저 넣는다(`_hold_pose`). 새 동작을 짤 때도 그렇게 한다.
- **블렌더 5.x는 새 키의 보간 설정을 `keyframe_insert`에 반영하지 않는다.** 5.2.3에서 CONSTANT로 두어도 BEZIER 키가 생겨, 숨겨 둔 인물이 제때 나타나지 않고 화면이 서서히 어두워졌다. 스크립트의 `key()`는 넣은 키의 보간을 직접 고친다. 새 코드에서도 `key()`를 쓴다.
- **5.x에는 `Action.fcurves`가 없다.** F-커브는 `action.layers[].strips[].channelbags[].fcurves`에 있다. `fcurves_of()`가 4.x와 5.x를 둘 다 읽는다.
- **세트는 X로 400 m씩 떨어져 있다.** 새 동작에서 목적지 좌표를 쓸 때는 세트 오프셋(`act["_offset_x"]`)을 더한다. 처음 코드에서 walk가 이것을 빼먹어 인물이 다른 세트로 걸어갔다.
- **방 세트 천장.** 천장이 없을 때 낮은 카메라에서 벽 위가 검게 비었다. 천장을 넣은 대신 위에서 내려다보는 구도는 쓸 수 없다. 창 발광을 세게 하면 방이 하얗게 날아갔다(지금 0.5).
- **세로 화면은 가로가 좁다.** 무대 가수가 화면 오른쪽 끝에서 잘려 카메라 from/to를 다시 잡았다. 인물을 가로로 여럿 세울 때는 lens를 줄이거나 뒤로 뺀다.
- **`finish.py`에 `--timeline`을 빼면 예제 제목·자막이 들어간다.**
- **블렌더는 `--python` 스크립트가 예외로 멈춰도 `--python-exit-code 1`이 없으면 종료 코드 0으로 끝난다.** 5.2.3에서 확인: 붙이면 1, 빼면 0. 그래도 로그 끝의 `Traceback`과 `SCENE_OK`·`RENDER_COMPLETE` 줄, 결과 파일을 직접 본다.
- **create_voxel.py 상대 경로는 스크립트 폴더 기준이다**(4절 경로 규칙). 작업 폴더 기준으로 쓰면 파일이 `scripts/` 안에 생긴다.
- **오타는 멈춘다.** 시간대 `"Night"`처럼 대소문자가 틀려도 `ValueError`로 멈춘다(조용히 다른 값으로 바뀌지 않는다).
- 5.2.3 로그의 `World.use_nodes` DeprecationWarning은 결과에 영향이 없다.
- `render-manifest.json`과 `frames/_signature.txt`에는 PC 절대 경로가 들어가지 않지만, .blend에는 글꼴·이미지 경로가 남을 수 있다. 남에게 넘길 때는 .blend와 렌더 산출물을 빼고 팩만 넘긴다.

## 8. 실측 시간

시험 환경: Windows 10, RTX 3070 Ti 8GB, Blender 5.2.3 LTS, 공통 예제 대본(1080×1920, 24fps, 15초, 360프레임).

| 단계 | 시간 |
|---|---|
| 장면 만들기(`create_voxel.py`, 관중 4000 포함) | 2초 |
| 스틸 12장(50%, 16샘플) | 3초 |
| 전체 360프레임(100%, 32샘플) | 렌더와 합성을 합쳐 168초(한 번 잼) |
| 합성(`finish.py`, 음성 없음) | 3초 |

- 결과: H.264 1080×1920 360프레임 + AAC(무음), 15.000초, 약 5.7MB. 자막 글꼴은 Noto Sans KR Bold로 잡혔다.
- 프레임 PNG 360장은 약 634MB.
- 음성·배경음 합성은 이전 예제(12초)에서 시험 음(10초 내레이션 자리 + 12초 배경음)으로 확인했다: 길이가 영상과 같고, AAC 48kHz 스테레오, 내레이션이 끝난 뒤에도 배경음이 남는다.

확인하지 못한 것
- Blender 4.5 LTS에서의 실행.
- macOS·리눅스, 그래픽 카드 없는 PC.
- 1분이 넘는 타임라인, 샷 10개 이상, 관중 4000명보다 큰 군중의 시간·메모리.
- 여름·겨울 공원, 방 안 walk, 걸음 속도 초속 1.5 m 초과. (evening 시간대는 예제의 공원·경기장 샷에서 확인했다.)
- 픽셀 글꼴로 넣은 제목 카드.
- 실제 사람 목소리나 TTS를 넣었을 때의 자막 싱크.

동작 시험(예제 밖, 2026-11-10): 공원 낮(spring)에서 wave·point·cheer·turn_head·shake, 방 낮에서 sit(t0 0과 1.0)·nod를 스틸로 확인했다. 머리 모양 short·long·bald·cap, 얼굴 4종, extras glasses·headset도 같은 시험에서 확인했다.

## 9. 완료 기준

```bash
ffprobe -v error -show_entries stream=codec_type,codec_name,width,height,r_frame_rate,duration -of compact out.mp4
```

- 비디오: h264, 1080×1920, 24fps.
- 길이: 마지막 샷 end와 같다(예제 15.000초, 360프레임).
- 오디오: aac 트랙이 있고 길이가 영상과 같다. `--audio`를 줬다면 내레이션이 들리고 `--music`을 줬다면 배경음이 섞여 있다.
- 검수 시트와 자막 스틸을 직접 봤다: 화면 밖 잘림, 겹침, 발 뜸, t0 전 자세, 얼굴 위 글자가 없다.
- 사용자에게 보고한다: 결과 영상 경로, 단계별 시간, 확인하지 못한 것, 남은 어색한 장면.

## 10. 라이선스

자세한 내용은 `LICENSES.md`.

- 블렌더로 만든 그림·영상·.blend 파일은 만든 사람의 것이다.
- 외부 3D 모델·텍스처·HDRI 같은 외부 소재는 쓰지 않았다. 모든 형태는 코드로 만든 상자다.
- 팩에는 글꼴 파일이 없다. Noto Sans KR은 SIL OFL 1.1, 맑은 고딕은 Windows 글꼴 라이선스를 따른다. 조건이 분명해야 하면 `--font`로 권리가 분명한 글꼴을 넘긴다.
- 음성·배경음은 팩에 없다. 사용자가 준비하고 사용 권리를 직접 확인한다.
- 참고한 인스타그램 연작은 화면 구성과 연출 방식만 참고했다. 그 계정의 캐릭터·제목·대본·영상은 팩에 없다.
- `bpy`를 쓰는 스크립트를 외부에 공개 배포할 때는 GNU GPL 호환 조건을 따라야 한다는 것이 블렌더 재단 안내다.

## 11. 쓰지 않는 것

영상 생성 AI, 이미지 생성 AI, 외부 유료 API를 쓰지 않는다. 내려받아야 하는 3D 에셋이나 텍스처도 쓰지 않는다. 모든 형태와 재질은 블렌더 내장 파이썬 코드로 만들고 ffmpeg로 마무리한다.
