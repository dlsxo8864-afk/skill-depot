# 퇴근각 · 클레이 제작

사용자가 선택한 저비용 제작 방식은 로컬 Blender의 절차적 캐릭터와 키프레임 애니메이션이다. 영상 생성 API를 기본 경로로 호출하지 않는다. 음성은 연결된 TTS 또는 제공 WAV를 사용한다. 기존 EP1~3 실사 완성본을 덮어쓰지 않고 별도 버전으로 납품한다.

## 이 시리즈에 맞는 제작 판단

- 원문을 익명화하고 핵심 사건과 추측을 구분한다. 새로운 해고 결과·연애 의도·보복을 사실로 추가하지 않는다. EP4 개인 연락, EP5 후배 평가, EP6 프린트물(해당 단락만)의 현재 대본은 assets/episodes.json에 있다. EP 번호는 제작 순서이며 기존의 내부 파일 ID와 혼동하지 않는다.
- 얼굴·의상 정본은 assets/characters.json의 F01~F03, M01~M03 및 저장한 .blend다. 시안은 승인된 캐스팅과 구분한다. 동일 캐릭터의 얼굴은 회차 사이에 다시 랜덤 생성하지 않는다.
- 립싱크 없는 인형극이다. 한 동작씩 읽히게 고개·눈썹·시선·손 목표를 연출한다. 몸통/가슴 튕김, 반복 끄덕임, 허공을 잡는 손을 감정의 대용으로 쓰지 않는다. 소품의 주인과 실제 손 접촉, 바닥 접지를 확인한다.
- 기본 세로 1080×1920, 24fps, 30초 이내. 실제 최종 WAV 길이를 먼저 잰다. 글자 수만으로 시간이나 자막 타임코드를 확정하지 않는다. 음성을 속도 조정했다면 타임코드에도 동일한 비율을 적용한다.
- 기존 Remotion 중앙 자막 스타일(900px 폭, 1080 기준 중앙 x=540, 하단290px, 한글 Bold64px, 어두운 외곽선)을 유지한다. 짧은 자막 진입 모션은 프레임 기반으로 작성한다. 실제 발화 자막 외 제목·EP·시리즈 텍스트는 재생 중 표시하지 않는다. 사건 전달에 필요한 네이티브 채팅·알림은 기존 승인 예외다.
- 썸네일용 렌더와 네이티브 타이포그래피를 분리한다. 합쳐진 썸네일을 이미지 생성기로 다시 편집하지 않는다.

## 실행

작업마다 새 폴더를 만들고 assets의 JSON과 scripts의 스크립트를 복사한다. 첨부 원본 예제는 그대로 보관한다. 로컬 실행 기록과 재현 명령은 [workflow.md](references/workflow.md)를 참고한다.

1. 제목·훅·나레이션·장면별 행동을 작성한다. 캐릭터 카탈로그와 표정 시트가 필요한 경우 `build_clay.py`의 catalog/expressions 모드로 실제 Blender 스틸과 .blend를 만든다.
2. TTS를 제출하고 반환된 request ID로 같은 작업만 조회한다. 최근 실행 엔드포인트는 `google/gemini-3.8-flash-tts`, 여성 Aoede/남성 Charon이다. 실제 실행 때는 연결 도구의 스키마와 가격을 다시 확인한다. API 인증 파일을 결과물에 넣지 않는다.
3. 최종 음성과 확정 대본을 정렬한다. 이번 결과는 fal의 ElevenLabs forced-alignment를 이용했다. 강제 정렬은 발화가 대본과 같다는 독립 검증이 아니다. 누락·반복·끝말 잘림은 별도로 검수한다. `prepare_timeline.py`는 정렬 문자와 대본의 동일성, 자막 순서, 끝시간 및 30초 제한을 검사한다.
4. 장면표에 맞춰 동작을 작성한다. `build_episode.py`는 현재 EP4~6에 대해 작성된 연출이다. **임의의 새 대본을 넣으면 새 동작이 자동으로 생기는 범용 생성기가 아니다.** 새 사건은 beat 분기·세트·동선·소품 소유권을 설계한 뒤 연결한다. 장면 수 자체는 7개로 강제하지 않는다.
5. Blender는 `-b --python-exit-code 1`로 별도 프로세스에서 실행한다. 사용자에게 열려 있는 .blend를 reset하지 않는다. 저장된 scene.blend와 각 장면 스틸을 검수한다. 세로 화면에서 얼굴, 손, 사건의 소품이 잘리는지 확인한다.
6. `render_frames.py`로 실제 프레임을 렌더한다. blend 해시·해상도·샘플 수가 캐시 서명에 포함된다. 같은 서명 내 정상 PNG만 재사용한다. 출력이 바뀌면 캐시를 공유하지 않는다.
7. `compose_episode.py`는 원본 프레임을 H264로 묶고 Remotion에 음성 및 Caption JSON을 전달한다. 프레임 수, 해상도, AAC, 디코딩 성공을 검사하고 최종 자막 장면을 직접 본다.

## 재사용 범위

EP1은 회의실·복도, EP2는 바·엘리베이터 등 별도 세트 설계가 필요하다. 이번 캐릭터 라이브러리만으로 기존 실사 연출이 자동 이전됐다고 표시하지 않는다. EP3는 승인된 나레이션·채팅·효과음을 유지하고 캐릭터 소스만 교체할 수 있다.

기존 원본 스킬의 7장면/프린터 사건 고정 조건은 예제 구현의 한계다. 새 라이브러리에 그대로 일반화하지 않는다. 실제 검증한 샘플과 계획 중인 제작 기능을 구분해서 알린다. 웹에 연결되지 않은 API·렌더 버튼을 작동 중이라고 표시하지 않는다.

## 납품

- 캐릭터별 PNG/.blend, 비교 시트, 표정 시트, 대본/음성/Caption JSON/SRT/장면표/.blend 및 실제 렌더한 MP4를 구분해 저장한다. 프레임 캐시와 node_modules는 납품 ZIP에서 제외한다.
- 기본 로컬 목적지는 `Desktop/업무/25. 썰 영상/퇴근각/블렌더-v2` 아래 캐릭터와 회차 폴더. 구글드라이브 납품이 승인된 기존 작업에서는 같은 버전·회차 구조를 따른다.
- EP3부터 게시글 메모는 각 회차 3안. 가볍게 묻기/친구와 공감하기/농담 섞기처럼 다른 말맛으로 각 본문 두 줄, 빈 줄 뒤 해시태그2~3개(`#회사썰` 기본). 설문·공지 말투를 피하고 경험담을 자연스럽게 유도한다. 영상 속 텍스트로 넣지 않는다.
- 실제 비용·실측 길이·검증 범위를 기록한다. 로컬 영상 렌더에 생성 API 과금이 없다는 사실과 TTS/정렬 서비스 비용은 구분한다.
