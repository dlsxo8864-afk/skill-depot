# AI Fight Arena 빌드·확장 명령어

너는 **겟앰프드 스타일 틱제 격투 RPG**를 만들고 확장한다. 여러 LLM(제미나이·클로드·GPT)이
각자 캐릭터를 조종해 1:1로 싸우고, 매 대전 후 스스로 반성하며 강해진다. 사람도 난입 가능.
목표: "누가 게임 컨트롤을 가장 잘 하는가"를 ELO·러닝커브로 겨룬다.

## 고정 설계 결정 (변경 금지 — 사용자가 명시적으로 바꾸라고 할 때만)
1. **전투는 틱제(턴제).** LLM 지연(1~5초) 때문에 실시간 프레임 조작 불가. 매 틱 양측이 행동 1개를
   고르고 **동시 판정**. 반사신경이 아니라 판단력으로 승부 → AI 지능 비교가 공정.
2. **핵심은 가위바위보 상호작용:** 타격 > 잡기 > 가드 > 타격, + 회피/강타/장풍/돌진타/회복/충전/이동.
   판정은 **결정적**(무작위 없음) — 운이 아니라 판단이 이긴다.
3. **AI 조종:** 공통 인터페이스 뒤에 Claude/GPT/Gemini 어댑터 + 규칙기반 봇(기준선) + 사람.
   각 틱 구조화된 관측을 받아 JSON 행동 1개 반환. 오류/지연/비합법 시 **안전 폴백**(게임 안 멈춤).
5. **자기학습 = 반성 기반 인컨텍스트 학습**(가중치 학습 아님): 매 대전 후 로그·결과를 근거로
   '전략 노트(플레이북)'를 다시 쓰게 하고 `data/memory/<provider>.json`에 누적 → 다음 결정에 주입.
   ELO·러닝커브로 학습 속도를 관측. scripted/human 은 학습하지 않는다.
6. **스택:** 백엔드 FastAPI + WebSocket(API 키는 서버측·메모리 보관, 디스크 저장 금지),
   프런트 HTML5 Canvas 단일 페이지. 포트 **8300**, 바인딩 **127.0.0.1**(localhost 금지).
7. **키/모델은 UI·.env 로 주입**하고 코드에 하드코딩 금지. Claude 는 anthropic SDK,
   GPT 는 openai SDK, Gemini 는 stdlib(urllib) REST. Claude 결정은 effort=low(속도).

## 프로젝트 위치
`C:\Users\<사용자>\Desktop\Claude\ai-fight-arena` (없으면 위 설계로 새로 생성).
구조: `server/{config,engine,agents,learning,app}` · `web/{index.html,game.js,style.css}` · `data/`.
스킬 추가 지점은 `server/engine/actions.py`의 `ACTIONS` 레지스트리, 판정은 `resolver.py`.

## 작업 방식
- **superpowers:brainstorming 은 이미 완료된 설계**를 따른다. 새 기능은 위 고정 결정과 일관되게.
- 코드 수정 후 반드시 검증: `python -m server.app` 로 서버를 띄우고(포트 8300), 브라우저 프리뷰로
  **봇 vs 봇** 대전을 돌려 엔진/전개/UI가 정상인지 확인(콘솔·네트워크 에러 점검). LLM 경로는
  키 없이 폴백으로 동작함을 확인하고, 실제 지능 검증은 사용자 키가 있을 때만.
- 한글 주석 허용, UTF-8/LF. 멈추지 말고 끝까지 완료하되, 되돌리기 어렵거나 비용 큰 동작은 먼저 알린다.
- 학습 데이터(`data/`)와 `.env`는 절대 커밋/유출하지 않는다.

## 이번 요청
`$ARGUMENTS` 에 따라 처리(비면 상태 점검 후 다음 할 일 제안):

- **new / (빈 값)** → 프로젝트가 없으면 위 설계로 전체 생성. 있으면 서버를 띄워 봇 대전으로 헬스체크하고
  현재 상태·다음 확장 후보를 요약.
- **run** → 서버 실행 + 브라우저 프리뷰로 봇 vs 봇 대전 시연 스크린샷.
- **add-skill <설명>** → `actions.py`에 새 행동 1개 추가(가위바위보 균형 유지), `resolver.py`에 상호작용
  규칙 반영, UI/프롬프트 규칙요약 갱신, 봇 대전으로 회귀 검증.
- **balance <설명>** → 피해/기력/쿨다운/사거리/우선순위 수치 조정. 조정 전후로 봇끼리 다수 대전을 돌려
  승률·평균 대미지로 균형 확인.
- **rpg <기능>** → RPG 확장(레벨/성장/장비/스킬트리/다인전 등). 엔진 순수성 유지, 모듈 경계 지키며 추가.
- **tune <설명>** → 에이전트 프롬프트·사고강도·온도·반성 프롬프트 개선. 학습곡선이 우상향하는지 확인.
- **그 외 자유지시** → 위 원칙 안에서 해석해 수행.

작업 목록(todos)을 만들고 순서대로 완료한 뒤, 실행 방법과 검증 결과(스크린샷/로그)를 사용자에게 보고한다.
